# AGENTS.md - tests

Three xunit projects.  `CONTRIBUTING.md` says what each runs and how; this file is the traps.

- **`tests/SqlSource.Tests/Generator/` is compiled twice, and three of its files three times.**  `tests/SqlSource.Tests.RoslynFloor` compiles the whole folder against Roslyn 4.8.0, so a test there uses only API that version has and hands the compiler C# 12 at most.  `GeneratorHarness.cs`, `InMemoryAdditionalText.cs` and `TestOptionsProvider.cs` are also compiled into `tests/SqlSource.Tool.Tests`, by exact path in its `.csproj`: a move or rename of one of them changes that file.  A helper the harness needs goes into one of those three files, not into a type of another folder.
- **`tests/SqlSource.Tests/Snapshot/TestSidecars.cs` is compiled into `tests/SqlSource.Tool.Tests` too**, by exact path in its `.csproj`, for `tests/SqlSource.Tool.Tests/SidecarFiles.cs`: a move or rename of it changes that file.  It uses the sidecar model and nothing else of its own project, and a helper it needs goes into the file itself.
- **Tests mirror the source folders.**  A test of `src/SqlSource/<Folder>/<Type>.cs` is `tests/SqlSource.Tests/<Folder>/<Type>Tests.cs`, and a test of the tool's `<Folder>/` is in `tests/SqlSource.Tool.Tests/<Folder>/`; `tests/SqlSource.Tool.Tests/Commands/` holds the tests that run a whole command line.  Namespaces follow folders, so a moved test changes its namespace.  The fakes and helpers of the tool's tests stay at that project's root, in `SqlSource.Tool.Tests`, which every sub-folder sees without a `using`; so do the tests of `ToolHost`, of `Outcome` and of a helper.
- **Multi-line values in `tests/SqlSource.Tests/SqlSource.Tests.csproj` are the test.**  `SqlSourceGeneratorParameters` and `SqlSourceDialect` are written with one word on each line, in the project and on items, to prove that the package's targets trim them before the compiler reads them.  Do not put them on one line.  The project imports the real `build/SqlSource.props` and `SqlSource.targets` for the same reason.
- **`tests/SqlSource.Tests/Snapshot/Examples/*.json` are copies of the sidecar format design**, sections 4.1 and 4.2 of `docs/superpowers/specs/2026-10-07-sidecar-format-design.md`.  A change to one changes the other, and `tests/SqlSource.Tests/Snapshot/SidecarExamples.cs` reads them from the output folder by that path.
- **`tests/SqlSource.Tool.Tests/Fixtures/Projects/` holds projects that are never built or restored.**  They are not compiled into the test project; `tests/SqlSource.Tool.Tests/Fixtures/FixtureProjects.cs` copies one out of the repository, with the package's MSBuild files and `global.json`, and the tests run the real `dotnet msbuild` on the copy.  A test that leaves an `obj` in the repository, or a file in a fixture, is a bug.  `OddPaths` holds a folder whose name has `;`, `=`, `%`, a quote and a non-ASCII letter on purpose.
- **No test of the tool waits for a time to pick an order, or changes the test process unseen.**  A test that needs the answers of `tests/SqlSource.Tool.Tests/FakeProcessRunner.cs` in an order, or several open at once, holds them with `tests/SqlSource.Tool.Tests/ProcessGate.cs` and not with `Task.Delay`.  A test that changes the environment of the test process is in the collection `ChangesTheEnvironment`, which runs alone, and puts back what it changed.  A test that starts a program of the operating system skips with `Programs.SkipUnlessOnPath` where the program is missing.  `tests/SqlSource.Tool.Tests/Commands/TerminationTests.cs` is the one test that starts the tool as a process: it runs the copy in the tests' output with `--roll-forward LatestMajor`, since the libraries beside that copy are of the tests' runtime, and it looks for the run's folder and for nothing else in the temporary directory, where a killed MSBuild leaves the pipes of its runtime.  Its project has a target that writes a file and then waits for two minutes, so that a test sends its signal when MSBuild has a program of its own running, and a run ends only when it is told to.  Its test of a closed console runs on Windows alone, so `nightly.yml` is the only place that runs it: a change to it is tried by starting that workflow by hand.
- **Allocation budgets are tests.**  `Parsing/SqlFileParserAllocationTests.cs`, `Generation/Paths/PathResolverAllocationTests.cs` and `Snapshot/Reading/SidecarReaderAllocationTests.cs` in `tests/SqlSource.Tests` hold a number of bytes.  Lower one when the code improves; never raise one to make a change pass.
- **`tests/SqlSource.Tests/Generator/CachingTests.cs` is what makes the generator's step names mean something.**  It reads each step's run reasons by its name in `TrackingNames`; a new step that does real work gets a case there.
- **`tests/SqlSource.Tests/Diagnostics/DiagnosticsDocumentTests.cs` fails when `docs/diagnostics.md` and the descriptors disagree.**  `tests/SqlSource.Tool.Tests/AnalyzerReleases.Unshipped.md` lists the one descriptor the tests bring themselves; a new one adds a row there.
- **Assertions are Shouldly's**, and test names are `Method_Scenario_Outcome`.  `.editorconfig` turns the analyzer rules off that this needs, under `[tests/**.cs]`.

> Maintenance: this file names specific files and folders.  If you rename, move, or remove them, update this file in the same commit.
