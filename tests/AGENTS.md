# AGENTS.md - tests

Seven xunit projects and the two libraries they share.  [`README.md`](README.md) says what each is, which Roslyn it runs on and how they reference each other; this file is the traps.

- **A test project compiles no `.cs` file of another project, with one exception.**  Code that two test projects need is in one of the two libraries, which they reference.  The exception is `tests/SqlSource.Tests/Generator/`, whose test classes `tests/SqlSource.Tests.RoslynFloor` compiles a second time against Roslyn 4.8.0; its own `AGENTS.md` says what that asks of a test there.  `tests/SqlSource.Tests/TestLayoutTests.cs` fails on any other `Compile` item of a test project that names a file outside the project's folder, however its path is spelled, on a file of `Generator/` whose name does not end in `Tests.cs`, and on one without the line that says it is shared.
- **The two libraries, `tests/SqlSource.Testing` and `tests/SqlSource.Tool.Testing`, hold no tests.**  `tests/SqlSource.Tests.RoslynFloor` references `SqlSource.Testing`, so it stays on the pinned Roslyn with no `VersionOverride`, and what that asks of the code is in the `AGENTS.md` of `tests/SqlSource.Tests/Generator/`.  Keep the two apart: the tool raises Roslyn to a current version, which would reach RoslynFloor through one library ([why](README.md#the-projects)).  Their types stay `internal`, except `SettingLevel` of `tests/SqlSource.Testing/Generator/LevelSettings.cs`, which a public theory takes as its row.  A helper that one test project alone uses stays in that project; one that a second project comes to need moves into a library.
- **A test reads a generated model by reflection through `ModelReflection` of `tests/SqlSource.Testing`**, which orders the properties by `MetadataToken`, the order they are declared in.  `Type.GetProperties()` does not promise that order, so a test never compares it.  `tests/SqlSource.Tests/ModelReflectionTests.cs` tests the helper.

A change to the calls a method makes changes the hand-written method with it, never the margin, and a change to the generated buffer changes `RowBufferByHand`, which `Generation/Emitting/RowBufferTests.cs` compares with it.  Three more tests on each engine hold the pooled method of each result member that copies its rows out, `ToArray`, `ToList` and `ToImmutableArray`, to a few hundred rows against a hand-written baseline of its own, a `List` + `ToArray()`, a `List` grown by doubling and returned as it is, and an `ImmutableArray` builder that is drained, which it must undercut by at least its `LeastSavingInBytesPerCall`, `LeastListSavingInBytesPerCall` or `LeastImmutableArraySavingInBytesPerCall`: each number is set from a measure, raised when the pool saves more, and never lowered to make a change pass.  A pooled result member needs such a test, since the pairs against `RowBufferByHand` use the buffer's own text and cannot see what it costs.  Both end-to-end `EndToEnd/AllocationTests.cs` measure through `CallAllocations` of `tests/SqlSource.Testing`, by the commonest difference of pairs of calls, never by a total, a median of blocks or the least of the calls, which move with what the driver and other threads allocate ([why](SqlSource.Testing/EndToEnd/CallAllocations.cs)).
- **The `Caching*Tests` classes of `tests/SqlSource.Tests/Generator/` make the generator's step names mean something.**  They read each step's run reasons by its name in `TrackingNames`, through `StepReasons` of `tests/SqlSource.Testing/Generator/`, whose `AllReasons` fails a test on a step that has lost its name; a new step that does real work gets a case in the class of its step.  `CachingScene` gives every run the project's settings file, an additional text of the driver, and MSBuild tells the generator nothing; a test that swaps the options for others changes `SqlSourceBuildFolders` alone.
- **`tests/SqlSource.Tests/Diagnostics/DiagnosticsDocumentTests.cs` fails when `docs/manual/diagnostics.md` and the descriptors disagree.**  `tests/SqlSource.Tool.Tests/AnalyzerReleases.Unshipped.md` lists the one descriptor the tests bring themselves; a new one adds a row there.
- **Assertions are Shouldly's**, and test names are `Method_Scenario_Outcome`.  `.editorconfig` turns the analyzer rules off that this needs, under `[tests/**.cs]`.  `Method` is what the test calls: the C# method in full, `DescribeAsync_` and never `Describe_`, or the command or statement it runs, as the `Describe_` of `DescribeCommandTests`, which runs `describe`, and the `Explain_` of `PlanOutputTests`, which runs the server's `EXPLAIN`.  A test of a value names the value as `Method` and what it is read under as `Scenario`, as `Patience_OfEveryWait_IsTwoMinutes`.  A test that needs another current culture takes it from `CultureScope` of `tests/SqlSource.Testing`, which puts back the one it found.  A unit-test class and a container class may share a name, as the two `NpgsqlCheckTests` do: their folders tell them apart.
- **Every test class is `sealed`**, a `partial` one `public sealed partial class`.  Nothing checks it; a new class follows the rest.
