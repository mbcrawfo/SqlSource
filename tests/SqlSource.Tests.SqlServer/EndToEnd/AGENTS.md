# AGENTS.md - tests/SqlSource.Tests.SqlServer/EndToEnd

- **`tests/SqlSource.Tests.SqlServer/EndToEnd/` is SQL Server's end-to-end project** ([what it covers](../README.md#the-end-to-end-project)).  Every sidecar of `EndToEnd/Queries/` is written by `tools/describe-end-to-end.sh` alone, never by hand, and `CheckTests` runs `--check` over the real project, never a copy, through `CliRun.Real`, as `ErrorPathTests` does.  No entry differs between the supported majors, since `CheckTests` runs on each, 2017 and 2025 in CI and 2019 and 2022 every night: a parameter that two majors type differently declares its type with `-- param:`, and a query of a type that 2017 lacks goes into `Queries/NewTypes.sql`, which `CheckTests` leaves out below 17, and its test skips by `SkipBelow(17, ...)`.  A query writes its parameters in camelCase, `@accountId`, so that its input model binds through Dapper.  A query runs through its generated method, the project's default being `codegen`; a file whose SQL a Dapper test runs is claimed a second time at the output `models`, by a class of `EndToEnd/DapperQueries.cs` in the namespace of its first claim, so that the two share its models, since a `codegen` query has a method and no constant.  A test of a query reads, asserts the values of at least one row, `NULL`s included, and takes its connection from `EndToEndSources`; a test that writes runs in a transaction that is rolled back and passes it as `transaction` to every call, of a method or of Dapper, since SqlClient refuses a command without it.  A test that must show that a commit succeeds commits only into a temporary table of its own connection, as the transaction test of `EndToEnd/StreamingQueryTests.cs` does, since a rollback cannot show that the transaction was not aborted.  A test that changes a setting of the session, such as `SET XACT_ABORT ON`, takes a connection that is not pooled from `EndToEndSources.AppUnpooled`, as `EndToEnd/XactAbortTransaction.cs` does, so that no other test gets the session.  `EndToEnd/ErrorPaths/` is a fixture project that the test project never compiles or describes: the `.csproj` removes it from `Compile`, `AdditionalFiles` and `None` and copies it to the output as `Fixtures/Projects/ErrorPaths/`.  A column of `all_types` changes `EndToEnd/app/schema.sql`, `EndToEnd/app/seed.sql` and `tests/SqlSource.Testing/EndToEnd/SqlServerAllTypesRows.cs` together, which holds its expectation and its property in `AllTypesProperties`, with its parameter in `WriteAllTypes`, declared `null`, and in `InsertAllTypes` or its row in `WriteSideLeftOut` of `EndToEnd/AllTypesQueryTests.cs`; `EndToEnd/ModelShapeTests.cs` and `tests/SqlSource.Tests.SqlServer.SqlClient61/AllTypesQueryTests.cs` compare the model with `AllTypesProperties` and keep no list of their own.  A change to `WriteSideLeftOut` changes the list of parameters Dapper cannot send in `docs/manual/recipes.md#dapper-with-sql-server`.  `EndToEnd/DapperRecipeTests.cs` proves what that part of the recipe says, and `EndToEnd/Types/TypedParameter.cs`, `EndToEnd/Types/DateOnlyHandler.cs` and `EndToEnd/Types/TimeOnlyHandler.cs` are the same code as its samples, in this repository's layout: a change to one changes the other.
