# The mutation scopes of the test review, which measure.sh runs one after another: each a part of one source project
# with the tests that mirror it.  No scope mutates a whole project, which does not fit in a night.
#
# A block is five lines, and blocks are apart by an empty line:
#   scope    the scope's name, which is its folder under mutation/ of a run folder
#   project  generator (src/SqlSource) or tool (src/SqlSource.Tool)
#   mutate   the globs of the source files, from the project's folder, apart by a space
#   tests    the filter of the tests, as tools/mutation-test.sh --tests takes it
#   folders  the test folders that the scope measures, apart by a space
#
# Every source file is in exactly one scope, and no test folder is in two.  A scope of a folder's own files runs the
# tests of that folder alone, without those of its sub-folders, which have scopes of their own.  The root files of a
# project are run with the tests that drive it whole, the generator's driver tests and the tool's command tests, and
# with the tests of those files.  tests/SqlSource.Repository.Tests/TestReview/SkillDataTests.cs checks this file.

scope generator-root
project generator
mutate *.cs
tests FullyQualifiedName~SqlSource.Tests.Generator.|FullyQualifiedName~SqlSource.Tests.DatabaseNameTests.|FullyQualifiedName~SqlSource.Tests.EquatableArrayTests.|FullyQualifiedName~SqlSource.Tests.PackageVersionTests.|FullyQualifiedName~SqlSource.Tests.SortedSearchTests.|FullyQualifiedName~SqlSource.Tests.SqlIdentifierTests.|FullyQualifiedName~SqlSource.Tests.SqlServerNamesTests.|FullyQualifiedName~SqlSource.Tests.SystemSchemasTests.|FullyQualifiedName~SqlSource.Tests.TextLinesTests.|FullyQualifiedName~SqlSource.Tests.UnexpectedEnumValueExceptionTests.|FullyQualifiedName~SqlSource.Tests.VersionsTests.
