# TD-0079 items 8 and 9 - the parameter binders and the helper of C# type text

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the two parameter binders one shape and move `PostgresTypeMap.AsWritten` to `ClrTypeName`, with generated code byte-for-byte the same.

**Architecture:** `SqlServerBinding`'s body becomes `SqlServerParameterBinder`, a subclass of `ParameterBinder` in a file of its own, as `PostgresParameterBinder` is.  The six values that stay the same for every parameter of a method (builder, indent, command, the parameter's local, the input's argument, the conversion names) travel as one `readonly record struct BindingContext`, so each `Append` takes `(in BindingContext, MethodParameter)`.  `ParameterBinder.AppendConverted` takes the cast and the text for null, and `PostgresParameterBinder.AppendValue` calls it instead of copying it.  `AsWritten` moves beside `ClrTypeName.KeywordTextOf`, the other helper of C# type text.

**Tech Stack:** C# (netstandard2.0 generator), xUnit, Shouldly.

**Where the code differs from the spec:** the spec bundles five values; the parameter's local is the same for every parameter of a method too (`locals.Parameter`), so the record holds six and `Append` takes it and the `MethodParameter`.  Item 7's text names `SqlServerBinding.Part` and `SqlServerBinding`; after this change those live in `SqlServerParameterBinder`, so item 7's text names that class and is otherwise left for td-0079-names.
