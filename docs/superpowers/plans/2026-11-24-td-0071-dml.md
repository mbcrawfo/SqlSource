# TD-0071 OUTPUT and UPDATE proofs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On SQL Server, prove not null the `OUTPUT inserted` column of a `PERSISTED NOT NULL` computed column of an `INSERT` or an `UPDATE`, an `UPDATE`'s `OUTPUT inserted` column that its `WHERE` keeps from `NULL` or its `SET` writes not null, the same `OUTPUT deleted` columns of an `UPDATE` or a `DELETE` (owner's Q1), and the columns of `cte-feeding-update`; lower SQL Server's noise budget from 5 to 1 and rewrite TD-0071 to what remains.

**Architecture:** A new reader, `OutputStatement`, reads `[WITH ...] UPDATE ... SET ... OUTPUT ... [FROM ...] [WHERE ...]` and `[WITH ...] INSERT ... OUTPUT ... <source>` into the parts the proofs already take: the `WITH` clause and CTEs as `SelectStatement` reads them, and a `SelectBody` whose items are the `OUTPUT` items and whose `FROM` and `WHERE` are the `UPDATE`'s, so `FilteredRows`, `ExpressionProofs`, `OperandsQuery.Calls` and `CteProofs` work on it unchanged.  `ColumnProofs.Read` falls back to it when `SelectStatement.Read` gives null.  An `inserted.c` item is never sent to the server: it is proved by the catalog, by the `WHERE` from the text and its row, or by the `SET` value's proof, which is a slice of the user's SQL asked over the `UPDATE`'s rows.  `FilteredRows.CteColumnOf` takes a CTE of one branch too, so `CteProofs` proves `outstanding`.

**Tech Stack:** C#, xUnit, Shouldly, SQL Server containers of the database tests.

**Spec:** `docs/tech-debt/TD-0071-sql-server-answers-nullable-for-columns-that-cannot-be-null.md`, the items "`OUTPUT inserted` of a computed column declared `PERSISTED NOT NULL`" and "A filter of an `UPDATE`", and the brief's slice 5: the columns of `cte-feeding-update`.

**Where the code differs from the spec:**
- The spec puts a `SET` proof in `RowFilter`.  `RowFilter` reads a `WHERE` alone, so the `SET` is read by `OutputStatement` and its value proved by a new `ExpressionProofs.OfAssigned`.
- `outstanding` is no `UPDATE` rule: it is a computed column of a CTE of one branch, which the merged `CteProofs` proves once `CteColumnOf` stops requiring several branches.  This also proves such a column in a `SELECT`, a release note.
- `CONCAT` needs no form: the server answers it not null over the rows (measured on 2025), so the `SET` value is an operand.

## Global Constraints

- A false non-nullable is the worst outcome; a misread proves nothing (`src/SqlSource.Tool/Describing/SqlServer/Proofs/AGENTS.md`).  Every new case has one that must stay unproved, unit and on a server (`ProofTests`).
- `operands` text stays slices of the user's SQL cut at token offsets, joined only by `SELECT`, `,`, line breaks and `AS [n]`, sent only as `@tsql`.  An `inserted.c` or `deleted.c`, or any item that holds `inserted .` or `deleted .`, is never an operand: the server refuses it in a `SELECT` and the whole call fails.  `DEFAULT` is never an operand either.
- Names compare ordinally, except that a column the `SET` writes is matched loosely (ignoring case, accents, kana and width), since a collation may make `Shipped_At` the column `shipped_at`, and ruling out a CTE's name compares ignoring case.
- Assume `ANSI_NULLS` and `ANSI_WARNINGS` on, as the other proofs do.
- Budgets of `RealisticNullabilityNoiseTests` move only for SQL Server: `[14] = 1, [17] = 1`.
- Every command through `zsh -lc '...'`; format with `./format.sh`; `./pre-commit-validation.sh` before each commit.

## Review Focus

- `UPDATE dbo.t SET ... OUTPUT inserted.b FROM dbo.t AS o WHERE o.b IS NOT NULL`: the target is not the aliased instance (measured: the server may cross join), so `inserted.b` must stay nullable.
- A `SET` that writes the filtered column, by any spelling: `SET o.b = NULL`, `SET B = NULL`, `SET @v = b = NULL`, `SET b += 1`, `SET b = DEFAULT`, must leave `inserted.b` unproved by the filter.
- An `UPDATE` through a view, a CTE or a derived table, and a `MERGE` (whose `inserted` is `NULL` for a deleted row), must stay nullable.
- A filter on another source's column of the same name (`WHERE u.b IS NOT NULL`, `inserted.b` of `o`) must prove nothing.
- An `OUTPUT` item that holds `inserted.` inside an expression (`COALESCE(inserted.b, 0)`) asks nothing and fails no call.

### Task 1: Read an `INSERT` or `UPDATE` with `OUTPUT`

**Files:**
- Create: `src/SqlSource.Tool/Describing/SqlServer/Proofs/OutputStatement.cs`
- Modify: `src/SqlSource.Tool/Describing/SqlServer/Proofs/SelectStatement.cs` (expose the `WITH` reader)
- Test: `tests/SqlSource.Tool.Tests/Describing/SqlServer/Proofs/OutputStatementTests.cs`

**Interfaces:**
- Produces:
  - `SelectStatement.ReadWith(IReadOnlyList<TsqlToken> tokens, int at, int end, List<CommonTableExpression> ctes) : int`, internal: the end of `WITH ctes` starting at the word `WITH`, or `-1`; `Read` uses it.
  - `internal enum OutputKind { Insert, Update }`.
  - `internal sealed record Assignment(string Column, TokenRange Value)`: a `SET` item `c = v` or `q.c = v`, `q` the target's name; `@v = e` gives none.
  - `internal sealed record OutputStatement(OutputKind Kind, TokenRange With, IReadOnlyList<CommonTableExpression> Ctes, SelectBody Rows, string Target, bool TargetIsAlias, IReadOnlyList<Assignment>? Assignments)`:
    - `Rows`: `Items` the `OUTPUT` items (`SelectItem.Read` of each comma-split item), `From`, `Where` and `FromThroughWhere` the `UPDATE`'s (null for an `INSERT` and when absent), `Grouping` `None`, no `HAVING`, `TOP` or `OFFSET`, `IsOneTable` false.
    - `Target`: the last part of the target's name; `TargetIsAlias` true when the `UPDATE` has a `FROM`.
    - `Assignments`: null when any `SET` item is not exactly one level-0 `=` between a column of one part, or of two whose first is `Target`, or a parameter, and a value.
  - `OutputStatement.Read(IReadOnlyList<TsqlToken> tokens) : OutputStatement?`
  - `OutputStatement.IsTargetColumn(IReadOnlyList<TsqlToken> tokens, string[] parts, string column) : bool`: `parts` names `column` of the target, ordinally: `[column]` when there is no `FROM` or the `FROM` has one source, or `[Target, column]`.
  - `OutputStatement.Writes(string column) : bool`: an assignment's column equals it ignoring case, accents, kana and width (`CultureInfo.InvariantCulture`, `CompareOptions.IgnoreCase | IgnoreNonSpace | IgnoreKanaType | IgnoreWidth`).

Rules of `Read`, each failure null: optional `;`, optional `WITH` (no `XMLNAMESPACES`), then `UPDATE` or `INSERT`, ending the text or before `;`.  Exactly one level-0 `OUTPUT` in the statement, no `INTO` in its items, no word of `SelectBody`'s statement words at level 0 after the first, balanced text.
- `UPDATE [TOP ( ... ) [PERCENT]] name [WITH ( ... )] SET ... OUTPUT ... [FROM ...] [WHERE ...] [OPTION ( ... )]`, the clauses in that order, each once; `name` 1 to 4 parts, not a parameter.  With a `FROM`, `name` is one part and `JoinChain.Read` of the `FROM` gives exactly one source of that `Name`, ordinally, which is not derived.  A one-part `name` that is a CTE's, ignoring case, gives null.  `WHERE CURRENT OF` gives null.
- `INSERT [TOP ( ... ) [PERCENT]] [INTO] name [WITH ( ... )] [( columns )] OUTPUT items` then `VALUES`, `SELECT`, `DEFAULT VALUES`, `EXEC` or `EXECUTE` at level 0; anything else after the items gives null.

### Task 3: The proofs of an `OUTPUT`

**Files:**
- Modify: `Proofs/ColumnProofs.cs`
- Test: `tests/SqlSource.Tool.Tests/Describing/SqlServer/Proofs/ColumnProofsOutputTests.cs` (new, beside `ColumnProofsComputedTests.cs`, with the helpers of `tests/SqlSource.Tool.Tests/ColumnProofsCases.cs`)

**Interfaces:**
- Consumes: Task 1's `OutputStatement`, Task 2's `OfAssigned`.
- Produces: `ColumnProofs.Read` reads an `OutputStatement` when `SelectStatement.Read` gives null, with the same check that the items are the visible rows one for one (`AreTheColumns`).  For item `i` and its visible row:
  A pseudo-table is `inserted` of an `Insert` or `Update`, or `deleted` of an `Update` or `Delete` (owner's Q1); an item of the other pseudo-table proves nothing.
  1. A lone item `p.*` of a pseudo-table: every row `IsProvedByTheCatalog` gets `catalog`.
  2. `p.c` (three tokens, `p` a pseudo-table ignoring case) whose row `IsProvedByTheCatalog`: `catalog`.
  3. Else, for an `Update` or `Delete`, and a row `NullableAsRecorded` and not `MayBeClr`, "the filter keeps `c`" meaning the row `SqlServerColumns.IsStored` and a column of `RowFilter.Read(tokens, Rows.Where).Columns` for which `IsTargetColumn(parts, c)`:
     - `deleted.c`: the filter keeps `c`: `Proof.Yes`, whatever the `SET` writes (the old value is the one tested).
     - `inserted.c` of an `Update`: no assignment `Writes(c)` and the filter keeps `c`: `Proof.Yes`.  Exactly one assignment writes it, with `Column` ordinally `c`: `OfAssigned(Value)`.  Anything else: no proof.
     - An item that holds `inserted` or `deleted` followed by `.` anywhere: no proof.
     - Any other item: `Of(item)`, with `ExpressionProofs(tokens, Rows, FilteredRows.Read(tokens, Rows, Ctes), asksLoneLeaf: true)`.
  4. Without a `FROM`, a proof that needs an operand is no proof, and no call is made.
  The calls are built as a branch's are now (`OperandsQuery.Calls`, cut guards, `Renumbered`), and `CteProofs.Read` takes `new SelectStatement(With, [Rows], Ctes)`; move the loop into a helper both paths call rather than copying it.  The CLR widening (`clrNull`, `asksOrigin`) is unchanged.
