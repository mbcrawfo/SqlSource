# Query generation 7.0: before the maps - implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer, by running code against the containers and drivers, the six questions of sub-phase 7.0 and every "Verify first" item of the phase 7 design, write the answers as `docs/superpowers/specs/2026-10-26-query-generation-phase-7-spike.md`, and amend the design and the epic outline where a finding changes a detail.

**Architecture:** One pull request of documents.  Throwaway console programs and image builds in the session's scratchpad, never committed, as 8.0's spike was ([its appendix](../specs/2026-10-24-query-generation-phase-8-spike.md) is the precedent); one results file per program and combination.  The tool is changed only for one probe of task 3, in the working tree, and restored before the task hands back.  The document, the design's amendments and the outline's row are written from the results files.

**Tech Stack:** .NET 10 SDK 10.0.401 (`net10.0` for the probes); Npgsql 8.0.9, 9.0.5, 10.0.3 with `Npgsql.NodaTime` and `Npgsql.NetTopologySuite` of the same version; Microsoft.Data.SqlClient 6.1.7 and 7.1.1; NodaTime, NetTopologySuite and `NetTopologySuite.IO.SqlServerBytes` at the versions each task names; Docker 29.4 on Apple silicon.

**Spec:** [`docs/superpowers/specs/2026-10-26-query-generation-phase-7-library-maps-design.md`](../specs/2026-10-26-query-generation-phase-7-library-maps-design.md), section "7.0 Before the maps" and every "Verify first" item; the epic's [phase 7 section](../specs/2026-10-07-query-generation-epic-design.md#phase-7---library-maps).

## Review Focus

- A NodaTime value at the edge of a SQL Server type (`0001-01-01`, `9999-12-31 23:59:59.9999999`, `datetime`'s 1753, `smalldatetime`'s 2079, `time`'s 24 hours, an offset of ±14:00) read and written without loss or with the driver's own failure: task 2's limit probes.
- An offset NodaTime allows and `DateTimeOffset` does not (seconds in the offset, ±18 hours): task 2.
- A PostGIS type in a schema other than `public`, or behind a domain or a typmod (`geometry(Point,4326)`): task 3's describer probes.
- Shared `SqlServerBytesReader` and `SqlServerBytesWriter` used from many threads at once: task 2's concurrency probe.
- The pinned PostGIS package leaving `apt.postgresql.org` after a newer one ships: task 3 checks `apt-archive.postgresql.org`.

### Task 2: SQL Server probes, NodaTime, JSON and NetTopologySuite (questions 2, 3 and 5)

Values: each type's minimum and maximum, `datetime`'s 1753-01-01 and 9999-12-31 23:59:59.997, `smalldatetime`'s 1900-01-01 and 2079-06-06 23:59, a value with ticks below `datetime`'s precision, `time` 00:00 and 23:59:59.9999999, a NodaTime value with nanoseconds below a tick, `datetimeoffset` at -14:00 and +14:00, an `OffsetDateTime` whose offset has seconds and one at +18:00, an `Instant` outside `DateTime`'s range, a `Duration` of 25 hours and of -1 second into `time`. - [ ] **Step 2: Q3, JSON.**  On 2025, a `json` column written with a `string` as `SqlDbType.NVarChar`, `Size = -1`, and read as `string` with `GetFieldValue<string>`; `GetFieldType` of it. - [ ] **Step 3: Q5, NetTopologySuite.**  On both servers, `geography` and `geometry` columns. A subtype read by casting `Read`'s result to `Point`, and to `Polygon` for a point (the exception).  Concurrency: one shared reader and one shared writer used by 16 tasks for 10 000 round-trips each of mixed shapes, compared with the single-threaded results; and the source of `SqlServerBytesReader` and `SqlServerBytesWriter` 2.1.0 read for instance fields written by `Read` or `Write` (report each field and whether a call writes it).
