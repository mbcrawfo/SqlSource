# Phase 7.2: generated conversions, and NodaTime on SQL Server - implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The generator's own conversions as a third origin of converters, `Library`, scoped to the engines and drivers they serve and replaced by a project's or a mapped type's converter; a library row as a place the planner converts; the emitted class of NodaTime's conversions; NodaTime's SQL Server rows, on request, end to end; and `SQLSRC282` for NodaTime below 3.1.9.

**Architecture:** A library's edges are `Converter` records the generator builds from `LibraryProbe` and adds to `ConverterSet` beside the project's and the mapped types', each carrying a `LibraryScope`: its library and the `ConverterTargets` (SQL Server, Npgsql before 10, Npgsql 10) it serves.  `MethodPlanner` gives each query its target and the planner sees only the converters that serve it.  A library row now sets `Place` and `Database`, like an override, so the planner converts it where an edge serves its target and leaves it to the driver otherwise, never with `SQLSRC279` or `SQLSRC280`.  Each `TypeMethods` names the libraries whose generated conversions its methods call; a source output emits each such library's class once.  `TypeMethods` also names the libraries its `codegen` queries use, and a library below its floor blocks those queries and is `SQLSRC282` once for the project.

**Tech Stack:** C# (`netstandard2.0` generator, Roslyn 4.8 floor), xunit v3, Shouldly, Microsoft.Data.SqlClient 6.1 and 7, NodaTime 3.1.9 and 3.3.7, SQL Server 2017 and 2025.

**Spec:** [`docs/superpowers/specs/2026-10-26-query-generation-phase-7-library-maps-design.md`](../specs/2026-10-26-query-generation-phase-7-library-maps-design.md), section 7.2 and the sections it relies on ("Generated conversions", "NodaTime", "The libraries' floors"); [the spike](../specs/2026-10-26-query-generation-phase-7-spike.md), questions 2 and 6.

## Global Constraints

- Generator: `netstandard2.0`, Roslyn 4.8.0; it names no library type in its own code, only as text it emits, `global::`-qualified.  Every pipeline record has value equality, collections in `EquatableArray<T>`; nothing a user writes may make the generator throw.
- NodaTime's SQL Server rows, exactly: `date` `global::NodaTime.LocalDate`; `time` `global::NodaTime.LocalTime`; `datetime2`, `datetime`, `smalldatetime` `global::NodaTime.LocalDateTime`; `datetimeoffset` `global::NodaTime.OffsetDateTime`.  All value types.  Below a type override, a column type and a marker, above the base map.  An alias type maps as its base; a CLR user type never takes a row.
- NodaTime's edges, exactly (argument → return: body, with `value` the argument):
  - `DateTime → LocalDate`: `global::NodaTime.LocalDate.FromDateTime(value)`; `LocalDate → DateTime`: `value.ToDateTimeUnspecified()`
  - `TimeSpan → LocalTime`: `global::NodaTime.LocalTime.FromTicksSinceMidnight(value.Ticks)`; `LocalTime → TimeSpan`: `new global::System.TimeSpan(value.TickOfDay)`
  - `DateTime → LocalDateTime`: `global::NodaTime.LocalDateTime.FromDateTime(value)`; `LocalDateTime → DateTime`: `value.ToDateTimeUnspecified()`
  - `DateTimeOffset → OffsetDateTime`: `global::NodaTime.OffsetDateTime.FromDateTimeOffset(value)`; `OffsetDateTime → DateTimeOffset`: `value.ToDateTimeOffset()`
  - `DateTime → Instant`: `global::NodaTime.Instant.FromDateTimeUtc(global::System.DateTime.SpecifyKind(value, global::System.DateTimeKind.Utc))`; `Instant → DateTime`: `value.ToDateTimeUtc()`
  - `DateTimeOffset → Instant`: `global::NodaTime.Instant.FromDateTimeOffset(value)`; `Instant → DateTimeOffset`: `value.ToDateTimeOffset()`
  - `TimeSpan → Duration`: `global::NodaTime.Duration.FromTimeSpan(value)`; `Duration → TimeSpan`: `value.ToTimeSpan()`
  - Every edge serves SQL Server only.  Method names are `<Return>From<Argument>` on the short names: `LocalDateFromDateTime`, `DateTimeFromLocalDate`, …, `InstantFromDateTimeOffset`, `DateTimeOffsetFromInstant`.
- Offered whenever the compilation references NodaTime (`LibraryProbe.NodaTime`), whether the switch is on or not; the switch decides only what an unmapped column becomes.
- Emitted only when a planned `codegen` method calls an edge of the library: one class per library, `internal static class NodaTimeConversions` in namespace `SqlSource`, whose file starts `// <auto-generated/>` and `#nullable enable` and compiles warning-free on .NET 8 and 10, with NodaTime 3.1.9 and 3.3.7.
- Replacement: a project's converter of an edge (argument, return) replaces the library's, and so does a mapped type's, with no diagnostic.  Replacement is per directed edge.
- A library row is exempt from `SQLSRC279` and `SQLSRC280`: where no serving edge fits, the type goes to the driver.  An override, a column type or a marker keeps 8.2's rules.
- `SQLSRC282`: an error, not configurable, with no position, once per project and library, when a `codegen` query uses the library (a property a library row typed, or a call of its generated conversion) and the library is below its floor; that query gets no method, and its models keep their types.  NodaTime's floor is 3.1.9, told by the identity version of the referenced assembly named `NodaTime`.  Title `A library is older than SqlSource supports`; message `This project references {0} {1}, and SqlSource needs {0} {2} or later for the query methods that use it, so they are not generated.  Update the package.`  The library's name is an argument, so 7.4 reuses the descriptor.
- Anti-goal: the existing end-to-end tests, the realistic corpora and the examples are unchanged, byte for byte, in their generated code; so is 7.1's `EndToEnd/NodaTime/` of PostgreSQL.
- Repository rules: `./format.sh` before validating; implementers run the tests that cover their change, the controller runs `./pre-commit-validation.sh --full`; a SQL Server end-to-end change runs on 2017 too (`SQLSOURCE_TESTS_SQLSERVER_IMAGE=mcr.microsoft.com/mssql/server:2017-CU31-GDR19-ubuntu-18.04`); docs per root `AGENTS.md` rule 4 and `docs/manual/AGENTS.md`; nothing recorded as tech debt, deferred or a follow-up: report it to the controller.

## Where merged code differs from the design, and calls made here

- **The library's place.**  A library row's `TypeMapping.Detail` is its place, `the NodaTime library` (`LibraryRows.PlaceOf`), so `QueryTyper.PropertyOf` sets `Place` and `Database` for it as for an override, and `PropertyType.Library` tells the planner to exempt it.  7.1's PostgreSQL rows become places too; their target serves no NodaTime edge, so they still go to the plugin, and 7.1's generated code must not change (Task 3 checks).  `SQLSRC250` to `SQLSRC252` cannot fire for a library row, whose type is never resolved, so their wording needs nothing; `SQLSRC251`'s `{3}` would read "in the NodaTime library" if it ever did.
- **A project's converter now applies to a PostgreSQL plugin row** where its edge fits: `DateTime → Instant` reads a `timestamptz` the plugin would have read.  That is the design's "a library row is a place", and a project with no such converter sees nothing change.
- **The target.**  `MethodDrivers` gains `PostgresAtLeast10` from `NpgsqlProbe.AtLeast10`, so 7.3's `JsonNode` edges can serve Npgsql before 10 alone.
- **SQLSRC282's general wording** carries the library's name as an argument, so 7.4 adds its two libraries with no new descriptor.
- **The emitted class is listed in `AttributeSource.GeneratedTypes`** if Task 5's test shows `CS0436` in a project that sees another's internals; otherwise not.

## Shape for 7.3 and 7.4

- A new kind of edge is a `Converter` with `Origin = Library` and a `LibraryScope`; 7.3's `JsonElement`/`JsonDocument` edges are `ConverterTargets.SqlServer`, `JsonNode`'s `SqlServer | NpgsqlBefore10`.  Add a `<Library>Conversions` static class beside `NodaTimeConversions` and a case in `LibraryConverters.Of` and `LibraryConversionSource.Of`.
- The serializer and the spatial read path are not edges: each adds its own branch to `ConversionPlanner.Plan` and its own field to `Conversion`, reusing `Conversion.Library` for emission.

## Review Focus

1. **A SQL Server project that references NodaTime and turns nothing on** gets byte-for-byte the same code: the edges are offered but touch no property.  Task 5 tests a `datetime2` column with no override in such a project.
2. **A PostgreSQL override `timestamptz=NodaTime.Instant` with NodaTime and no plugin** keeps today's behaviour, the type trusted to the driver, no `SQLSRC279`, no conversion: the SQL Server edges must not serve it.  Task 3 tests it.
3. **A nullable NodaTime column and a nullable parameter**, `LocalDate?`, read and sent with `NULL` both ways, and an array never arises on SQL Server.  Task 7 tests nulls end to end; Task 5 compiles a nullable read and write.
4. **A project converter of one direction** (`DateTime → LocalDate` only) replaces the library's read and keeps the library's write.  Task 5 tests it.
5. **A NodaTime below 3.1.9 that only a `models` query sees** reports nothing; one that a `codegen` query uses blocks only the queries that use it.  Task 6 tests both.
