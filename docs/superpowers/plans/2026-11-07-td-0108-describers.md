## Decisions made here (where the merged code or an owner question settles what the spec left open)

- **Item 21 takes the remark path, pending the owner's Q1.**  At a root `ModifyTable` whose SQL names `OLD` or `NEW`, `ColumnOf` maps a bare name to `BareAlias` and `Expressions.InstanceOf` refuses it.  PostgreSQL prints bare names for a single-target statement on every major, and the flag is a word check that also fires on 14–17.  Unifying in either direction would change answers on 14–18, so this unit keeps both rules.  They share one `Plans.InstanceOf`, which takes the bare-name rule as an argument, and a remark says why they differ.  If the owner answers otherwise, Task 6 changes.
- **Item 24:** `ColumnNullability.IsTable(...)` takes what the three sites hold.  `OutputFits` holds a `ColumnOrigin` whose `Table` is a relation row, so the helper takes that row type: `IsTable(PostgresRelationRow? table)`.  Use the record's real name; the implementer checks it.

## Review Focus

- A refactored reader that silently changes an edge case: an empty span or a trailing comma in item 25's comma split, or a hidden row with `IsNullable` null in item 23.  The existing tests and fixtures must pass unchanged, and the new enumerator gets a test of the empty-span choice.
- A form added to item 22's table but read by only one of the two readings.  The exhaustive switch makes that a build error.
- Group state left wrong after an early return inside a group (item 25).  `InGroup` restores it in a `finally`.
- An exception thrown on a path that used to return null, from a factory or a helper that is stricter than the code it replaces (items 26 and 28).  Factories add no validation.
- A diagnostic's text changed by the move (item 17).  The generator's diagnostics tests compare the messages, and nothing about them may change.
