## Global Constraints

- A test starts a program through `Programs.RunAsync`, never `Process.Start` (`tests/AGENTS.md`).
- `Eventually.Patience` (two minutes) is the one limit a test waits on, and every caller of `Programs.RunAsync` passes it (`tests/AGENTS.md`).
- A test that starts a program of the operating system skips with `Programs.SkipUnlessOnPath` where it is missing (`tests/SqlSource.Tool.Tests/AGENTS.md`).
- Resolving an item deletes its file, its row in `docs/tech-debt/README.md` and every reference to its id (`docs/tech-debt/AGENTS.md`).

## Where the code differs from the specs

- TD-0083's `ProgramsTests` guard cannot be `Eventually.Patience` itself: the test proves `RunAsync` gives up at the 200 ms it was given, and a guard as long as the default would let a `RunAsync` that gave up 30 or 60 seconds late pass.  It becomes `Eventually.Patience / 6`, 20 seconds today, unchanged.
- TD-0083's `Soon` stays below the outer `RunAsync`'s `Eventually.Patience`, or that limit would fire first and lose the test's own message with `taskkill`'s answer: `Soon` becomes `Eventually.Patience / 2`, 60 seconds today, unchanged.  The MSBuild target's wait becomes twice the patience (240 seconds), longer than every wait of both tests that use it; today the SIGTERM test's `RunAsync` patience and the wait are both 120 seconds, a tie.
- The `tests/AGENTS.md` fallback (naming the two as exceptions) is not taken.

## Review Focus

1. The SIGTERM/SIGHUP test on Unix: a run that ignored its signal must still be waiting when `RunAsync`'s patience ends — the target's wait must be longer than `Eventually.Patience`.
2. A Unix machine without `mkfifo` on the path: the named-pipe test skips instead of failing.
3. `CancelOnRead.FromDatabase` called with no source set in its flow (any other query or test): it cancels nothing.
4. The value set by `RunTimeArgumentTests` must reach the converter: the generated method runs in the test's async flow, so the `AsyncLocal` value flows into it.
5. Windows: the named-pipe test still skips there (msys `mkfifo` may be on the path but makes no pipe the describer would see as one).
