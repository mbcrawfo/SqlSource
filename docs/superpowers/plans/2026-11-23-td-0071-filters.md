# TD-0071 WHERE and set operator proofs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SQL Server columns that a top-level `WHERE` conjunct keeps from being `NULL`, and columns of a `UNION`, `INTERSECT` or `EXCEPT` whose every branch proves them, are answered not null.

**Architecture:** `SelectStatement` reads a query as one or more branches, each a `SelectBody`.  Each branch has its own `ExpressionProofs` and its own `operands` text, and a column is proved when its item is proved in every branch.  `RowFilter` reads a branch's `WHERE` into the columns it keeps from being `NULL`, and `JoinChain` reads its `FROM` to find the `LEFT JOIN`s the filter makes inner and the CTEs a column is read through.

**Tech Stack:** C#, xUnit, Shouldly, SQL Server 2017 to 2025 in containers.

**Spec:** `docs/tech-debt/TD-0071-sql-server-answers-nullable-for-columns-that-cannot-be-null.md`, slice 2 of 5.

## Global Constraints

- A false non-null is the worst outcome and a false nullable only noise: whatever the reader cannot follow proves nothing.
- A filter reads a value and the result reads it again, so a filter proves a column only when the column is stored (`Proof.Stored`) or the server answers it not null.
- Every new proof has server tests of the queries that try to break it, in `ProofTests`.
- `README.md` is not edited.  No new tech-debt id.

## Measurements

On 2017 (CU31-GDR19) and 2025 (CU9-GDR1).

| Fact | Result |
|----|----|
| `ANSI_NULLS OFF`: `t = @p` and `@p = t` with `@p` `NULL`, `t <> @a` and `t != @a` with `@a` a value | Keeps the rows where `t` is `NULL` |
| `ANSI_NULLS OFF`: `LIKE`, `NOT LIKE`, `<`, `>`, `>=`, `!<`, `<>` of a literal, `t = t`, `<>` of an expression | Keeps none |
| `ANSI_NULLS ON`: every comparison and `LIKE` above | Keeps none |
| The server on `o.nn`, `NOT NULL`, through `LEFT JOIN` | Nullable |
| The same query with the words `LEFT` cut | Not null |
| That query with a later `RIGHT JOIN` | Nullable |
| A derived table's constant or `ISNULL` on the optional side of a `LEFT JOIN`, filtered | No row with no match is kept |
| A `UNION` of a `geometry` and the string `'NULL'` | One `NULL` row, and the column is of type `geometry`, which `MayBeClr` refuses |
| A filter on a value that changes, through a derived table, a computed column or a view | No `NULL` over 5,000 rows, which no plan promises, so `Proof.Stored` is required |

## Review Focus

- `OR` at the `WHERE`'s level, a `NOT` before a conjunct, and the `AND` of a `BETWEEN`.
- `x > ALL (empty)`, which is true for a `NULL` `x`.
- `ROLLUP`, `CUBE`, `GROUPING SETS` and `GROUP BY ALL`, which return `NULL` or rows the `WHERE` removed.
- A name written differently in the item and the filter, a name of another table, and a case-sensitive collation.
- A nested join, `a LEFT JOIN b JOIN c ON p ON q`, an `APPLY`, a comma, a join hint, and the function `LEFT(x, 1)` in an `ON`.
- A value that changes between the filter and the result.
- A CTE read on the optional side of a join, a CTE whose name differs only in case from a table, and a recursive CTE.
- A branch that proves nothing, a `NULL` branch, and a CLR type in one branch.

### Task 1: The branches

**Files:**
- Modify: `Proofs/SelectStatement.cs`, `Proofs/SelectBody.cs`, `Proofs/ColumnProofs.cs`, `Proofs/OperandsQuery.cs`, `Proofs/Proof.cs`, `SqlServerSession.cs`
- Test: `SelectStatementTests`, `ColumnProofsTests`, `OperandsQueryTests`, `SqlServerSessionProofTests`

- [ ] `SelectStatement.Branches` holds each `SelectBody`, split at `UNION [ALL]`, `EXCEPT` and `INTERSECT` of the query's level, a parenthesised branch read inside its parentheses.
- [ ] `ColumnProofs` proves an item in each branch, shifts each branch's operand indexes, and exposes one `operands` query per branch that asks.  A lone leaf is asked in a query of several branches.
- [ ] The session asks each query in order.  A query that proves nothing leaves its operands unanswered.

### Task 2: The filter

**Files:**
- Create: `Proofs/RowFilter.cs`, `Proofs/JoinChain.cs`
- Modify: `Proofs/ExpressionProofs.cs`, `Proofs/OperandsQuery.cs`
- Test: `RowFilterTests`, `JoinChainTests`, `ExpressionProofsTests`, `OperandsQueryTests`

- [ ] `RowFilter` reads the conjuncts: `x IS NOT NULL`, a comparison and `[NOT] LIKE` of a column written alone.  Any `OR` at the level gives none.
- [ ] `JoinChain` reads a left-deep chain of joins, and gives each source's exposed name and whether a join can make it `NULL`.
- [ ] A leaf that the filter keeps from being `NULL` is `AnyOf(Operand, Stored)`.
- [ ] The `LEFT [OUTER]` of a join whose source a conjunct filters is cut from the `operands` text, so the server answers that side's columns as an inner join's.

### Task 3: The CTE

- [ ] A column read from a CTE that no join can make `NULL` is kept from `NULL` when the CTE is one `SELECT` whose item at that place is a column its own `WHERE` keeps from `NULL`, or a column read in the same way from an earlier CTE.
