# TD-0051 rest, part 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the last fixable kinds of PostgreSQL column not null: a view's column, a `RETURNING` column of a value an `INSERT` writes, and an expression over a partitioned `ModifyTable` target.

**Architecture:** A view's column is read from the entry the plan prints for it, as a column of no origin is.  A written value is read from the child of a root `Insert`, by the column's number, and counts only after a new call, `triggers`, finds no `BEFORE` row trigger that could change it.  `relations` also asks for the target of a root `ModifyTable`.

**Tech Stack:** C#, .NET 8, PostgreSQL 14 to 18, xunit, Shouldly.

**Spec:** `docs/tech-debt/TD-0051-columns-that-cannot-be-null-are-answered-nullable.md`

## Global Constraints

- A false non-null is the worst outcome: a form that cannot be proved stays unproved, and the item says so.
- The owner's decision: prove a written value for `INSERT` only, with no `BEFORE` trigger or rule on the target.  Exclude `INSERT ... ON CONFLICT DO UPDATE` and a `BEFORE` trigger on any partition of a partitioned target.  `UPDATE` stays a documented limit.  Each exclusion is pinned by a test on a real server.
- A call of `PostgresCallNames` is added and never renamed, and its SQL qualifies every name and operator.
- A key the walk reads is a constant of `PlanKeys` and gets its kind in `PostgresPlanRenamer`.

## Where the spec and the code differ

- A view can hide an outer join from the query's text, and a negated list reduces that join as it does a written one.  So a query with a negated list distrusts join reduction whether or not its text is gated.  This also closes the same false non-null for an expression over such a view.
- A written parameter is not proved, so `insert-select-returning` `note` stays nullable.
- `UPDATE` and `DELETE` on a partitioned target print a partition's alias, `p_1.id`, which names no instance, so only an `INSERT`'s expression over the target is proved.

## Review Focus

- A view over an outer join, and one whose join a negated list reduces in the plan.
- A `BEFORE` row trigger on the target or on one partition, enabled or disabled, that sets the column to `NULL`.
- `ON CONFLICT DO UPDATE`, which may return a row the statement did not write.
- A dropped column before the written one, a generated column, and a `DEFAULT`.
- A statement that names `OLD` or `NEW`, and a `RETURNING` entry that is another column under the name.
