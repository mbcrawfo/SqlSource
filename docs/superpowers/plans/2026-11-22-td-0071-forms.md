# TD-0071 forms: date functions, `LAG` and `LEAD`, and the `CASE` that guards a column

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove not null, on SQL Server, the date functions and `AT TIME ZONE` of operands that are not null, `LAG` and `LEAD` with a default, and `CASE WHEN x IS NULL THEN e ELSE x END`, and lower `Budgets` by what they prove.

**Architecture:** Each is a form of `ExpressionProofs`, read from the tokens, with the operands it needs asked through the existing `operands` call.  One new fact comes from that call's answer: whether an operand is a stored column of a table.

**Tech Stack:** C#, xUnit v3, Shouldly, SQL Server 2017 to 2025 in Docker.

**Spec:** `docs/tech-debt/TD-0071-sql-server-answers-nullable-for-columns-that-cannot-be-null.md`, slice 1 of 5.

## Where the code differs from the spec

- **The `CASE` form is not "a form of the text alone".**  It reads `x` twice.  SQL Server evaluates a repeated expression once per reference, and `COALESCE(<NEWID() expression>, 0)`, which it expands to the same `CASE`, returned `NULL` in about half its rows on 2017 and 2025.  So `x` must be a name that the server answers either not null or a stored, non-computed column of a table.  A computed column, a view's column and a derived table's expression gave no `NULL` in 5 runs, but nothing promises that, so they stay unproved unless the server answers them not null.
- **`COALESCE` itself has this bug on `main`.**  It is outside this slice and went to the manager as Q1.  This plan does not touch it.

## Measured on 2017 (CU31-GDR19) and 2025 (CU9-GDR1)

- Every date part over every date and time type at both ends of its range, through `DATEADD`, `DATEDIFF`, `DATEDIFF_BIG`, `DATEPART`, `DATENAME`, `YEAR`, `MONTH`, `DAY` and `EOMONTH`: a value or an error, never `NULL`.
- `AT TIME ZONE` at the ends of the range and across a daylight-saving gap: a value or error 9813.  An unknown zone is error 9820, and a `NULL` zone is `NULL`.
- Each of these forms refuses a CLR operand when described (206 or 8116), so none needs its operand's type asked.
- With `ANSI_WARNINGS` and `ARITHABORT` off, an implicit conversion overflow makes `DATEADD(DAY, 1, 1e10)`, `DATEDIFF`, `DATEPART`, `DATENAME` and `YEAR` `NULL`; with `ANSI_WARNINGS` on it is error 8115.
- `LAG` has its operand's type.  `LAG(g, 1, 'NULL')` of a `geometry` converts the default to that type's Null.  A default of a CLR type over a non-CLR operand is refused.  `LAG(x, 1, 300)` of a `tinyint` is `NULL` with both settings off and error 220 with `ANSI_WARNINGS` on.

## Global Constraints

- A false non-nullable is the worst outcome; a false nullable is only noise.  Anything unread proves nothing.
- A new form is a row of `FormsByName` and an arm of both `Form` and `FormType`.
- Every new proved form has a test on a server that it gives no `NULL`, and queries that try to break it and must stay nullable.
- `Budgets` of SQL Server move to what the run measures, on 14 and on 17.

## Review Focus

1. An `x` read twice that can change between reads: a computed column with `NEWID()`, a view's column, a derived table's expression.
2. `CASE` shapes one token from the form: a second `WHEN`, `IS NOT NULL`, another column in `ELSE`, `x` in brackets on one side only.
3. A CLR value reached through `LAG`'s or `CASE`'s conversion of a string, `'NULL'` above all.
4. `AT TIME ZONE` with a `NULL` zone column, a parameter as zone, or a chain where one link can be `NULL`.
5. `LAG` with a parameter, `NULL` or an expression as offset or default, a named window, and a grouping set that makes its operand `NULL`.
