# TD-0109 test names Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every `[Fact]` and `[Theory]` of `tests/` is named `Method_Scenario_Outcome`, with `Method` the method, command, statement or value the test calls (items 19 and 54 of TD-0109), and TD-0109 is resolved.

**Architecture:** Renames only.  Each task renames the tests of one group of test projects, with every copy and every reference to the old name in the same commit; no body, attribute, row or assertion changes.  The last task deletes TD-0109.

**Tech Stack:** C#, xunit v3, Shouldly.

**Spec:** `docs/tech-debt/TD-0109-duplicated-arrangements-and-uneven-conventions-in-tests.md`, items 19 and 54 and their proposed fixes.

## Global Constraints

- The rule, from `tests/AGENTS.md`: "test names are `Method_Scenario_Outcome`" and "`Method` is what the test calls: the C# method in full, `DescribeAsync_` and never `Describe_`, or the command or statement it runs, as the `Describe_` of `DescribeCommandTests` and the `Explain_` of `PlanOutputTests`.  A test of a value names the value as `Method` and what it is read under as `Scenario`, as `Patience_OfEveryWait_IsTwoMinutes`."
- Item 19's fix: "Give each two-part name a scenario and merge each four-part one into three."  Item 54's: "Name each test after the method it calls, in the originals and their copies together."
- Renames only: a new name says no more than the test checks; when the old outcome claims more than the assertions, the new one is narrowed to them.
- A copy is renamed with its original, to the same name: `DatabaseTests/Postgres/EndToEnd/ListQueryTests.cs` and `DatabaseTests/Postgres.Npgsql8/ListQueryTests.cs`; the Postgres `EndToEnd/Json/JsonQueryTests.cs`, `EndToEnd/NodaTime/NodaTimeQueryTests.cs`, `EndToEnd/NetTopologySuite/NetTopologySuiteQueryTests.cs` and their `Postgres.Npgsql8` copies; the SQL Server `EndToEnd/ListQueryTests.cs`, `EndToEnd/Json/JsonQueryTests.cs`, `EndToEnd/NetTopologySuite/NetTopologySuiteQueryTests.cs` and their `SqlServer.SqlClient61` copies.
- Every reference to an old name changes with it: `nameof`, comments, docs, `AGENTS.md` files, `tools/`, `.github/`.  `grep -rn --exclude-dir=bin --exclude-dir=obj '<old name>' .` finds none afterwards.
- Lines stay within 120 columns (the editorconfig check); run `./format.sh`.
- Counts on the tree of 2026-11-08 (main at f82d037b), which differ from the spec's: 7,364 tests, 104 of two parts and 16 of four (the spec's 102 and 15 predate the merged test units; a first count of 7,230 missed the tests whose attributes run over several lines); item 54's are 24 in each PostgreSQL `ListQueryTests` (spec 23), 22 in each SQL Server one, 12 in `EndToEndTests` (with 10 more there whose first part is a location or a type shape) and 1 in `SettingsLevelReaderTests`, with 8 names of `LibraryTypeTests` whose first part is `Detected_`, `NotDetected_`, `Default_` or `CodeGen_`.

## Review Focus

- A name whose `Method` is a scenario or short form though it has three parts (item 54's kind) in a file the task touches: the reviewer expects the file's names fixed together, not only those of two or four parts.
- An old name left in a comment of a sibling test (for example "One id more than TwoLists_AtTheLimit_Runs sends") or in a doc.
- A copy renamed differently from its original, or not at all.
- A new outcome that claims more than the assertions check.
- A rename that breaks `RoslynFloor`, which compiles `tests/SqlSource.Tests/Generator/` again.
