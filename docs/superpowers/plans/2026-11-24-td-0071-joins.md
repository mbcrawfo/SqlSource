# TD-0071 join tree proofs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove on SQL Server `COALESCE` over a column of each side of a `FULL JOIN`, and a computed column read from a table no join of the `FROM` can make `NULL`, a non-persisted one through its `sys.computed_columns.definition`; lower SQL Server's noise budget from 7 to 5 and rewrite TD-0071 to what remains.

**Architecture:** The merged `JoinChain` already reads a left-deep `FROM` as a tree of joins: each join's left side is the chain before it, its right side the one source it adds.  It records each source's reference and where its join starts, so that `FilteredRows` can give the two sides of the chain's last `FULL JOIN` as slices of the user's `FROM`.  `ExpressionProofs` numbers each operand with a scope, the branch's own rows or one side alone, and one shared builder, `OperandsQuery.Calls`, makes one `operands` call per scope and places each operand's answer, for `ColumnProofs` and `CteProofs` alike.  A computed column gets its definition as a new nullable member of the `columns` row, read from `sys.computed_columns`, and `ComputedProofs` proves that definition with `ExpressionProofs` over facts that the existing `table` call gives of its table's columns.

**Tech Stack:** C#, xUnit, Shouldly, SQL Server containers of the database tests.

**Spec:** `docs/tech-debt/TD-0071-sql-server-answers-nullable-for-columns-that-cannot-be-null.md`, the items "A computed column read through a join" and "`COALESCE` over both sides of a `FULL JOIN`".

**Where the code differs from the spec:**
- The spec asks for the `FROM` read as a tree of joins.  `JoinChain` (#407) reads a left-deep chain, which is that tree; a nested join (`a JOIN b JOIN c ON p ON q`) or a parenthesized one stays unread and remains a limit.
- The spec's `FULL JOIN` rule requires the `ON` to compare the two arguments with `=`.  Every row of a `FULL JOIN` has its left or its right side whatever the `ON`, so this plan builds it without that check; Q1 to the owner asks whether to keep it.

## Global Constraints

- A false non-nullable is the worst outcome; a misread proves nothing (`src/SqlSource.Tool/Describing/SqlServer/Proofs/AGENTS.md`).  Every new case has one that must stay unproved, unit and on a server (`ProofTests`).
- `operands` text stays slices of the user's SQL cut at token offsets, joined only by `SELECT`, `,`, line breaks and `AS [n]`, sent only as `@tsql`.
- A proof that reads a value twice uses `OneValue` (`COALESCE`).  Names compare ordinally, except that ruling out a CTE's name compares ignoring case.
- A member added to `SqlServerColumnRow` is nullable and gets its rule in `SqlServerFields.cs`; the fixtures are recorded again with `tools/record-fixtures.sh mssql`.
- Budgets of `RealisticNullabilityNoiseTests` move only for SQL Server: `[14] = 5, [17] = 5`.
- Every command through `zsh -lc '...'`; format with `./format.sh`; `./pre-commit-validation.sh` before each commit.

## Review Focus

- `a FULL JOIN b ON ... FULL JOIN c ON ...`: `COALESCE(a.x, c.y)` must stay nullable (a row of `b` alone), and `COALESCE(a.x, b.y)` too, since a later `FULL` or `RIGHT JOIN` can drop both.
- A `FULL JOIN` whose left side holds a `LEFT JOIN`: `COALESCE(l2.x, r.y)` with `l2` the optional source must stay nullable (the side's own answer says so).
- A computed column read from the optional side of an outer join, through a CTE, a derived table, a view, or a one-part name that is a CTE's in another case, must keep the server's answer.
- A computed column whose definition reads a nullable column, calls a user's function, or is of a CLR type must stay nullable.
- An older capture without the new `table` call, or a `table` call that fails for the computed column's table, never fails the describe unless the table match itself needs that table.

A scope whose `FromOf` is null gets no query, and its operands' places are past the end, where no answer is.

The rule, in `Coalesce`: an argument `a_j` and an earlier `a_i` of the other side prove the `COALESCE` with `AllOf([.. before, j is last ? Yes : OneValue(a_j), SideLeaf(a_i), SideLeaf(a_j), StoredLeaf(a_j)])`, `before` being the `OneValue` of every argument before `a_j` (so `a_i`'s among them), and `SideLeaf(a)` the operand `a` asked in its side's scope, `Proof.No` in the select's context under a grouping set.
