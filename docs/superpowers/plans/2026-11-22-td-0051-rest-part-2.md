# TD-0051 rest, part 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove four more kinds of PostgreSQL column not null: the owner's function rows, a count or `GROUPING` under grouping sets, a window aggregate whose frame holds the current row, and the literal columns of a `VALUES` statement.

**Architecture:** Function rows widen `TotalFunctions`.  Grouping sets get a path of their own that reads only a whole `count` or `GROUPING` at the grouping `Aggregate`.  A window's frame is read from the plan's `Window` key.  A `VALUES` statement's rows are read from the SQL, and count only when the plan is a `Values Scan` under nodes that never project.

**Tech Stack:** C#, .NET 8, PostgreSQL 14 to 18, xunit, Shouldly.

**Spec:** `docs/tech-debt/TD-0051-columns-that-cannot-be-null-are-answered-nullable.md`

## Global Constraints

- A false non-null is the worst outcome: a form that cannot be proved stays unproved, and the item says so.
- A form is pinned in `PlanOutputTests`, as 14 and 18 print it, before it is read.
- A key the walk reads is a constant of `PlanKeys` and gets its kind in `PostgresPlanRenamer`.
- Function rows are the owner's list alone: `abs`, `ceil`, `floor`, `round` and `trunc`.  Enum, domain and range forms stay limits.

## Where the spec and the code differ

- `round(numeric)` and `trunc(numeric)` are SQL functions the planner inlines, printed `round(a, 0)` and `trunc(a, 0)`.  So the rows are the two-argument forms, which are `internal`.
- Only PostgreSQL 18 prints a `Window` key; 14 to 17 print `OVER (?)`.  So a window aggregate is proved on 18 alone.
- A frame with an offset stays unproved.  A `RANGE` offset's bounds depend on the order type's `in_range` function, so only `UNBOUNDED` and `CURRENT ROW` bounds, with no `EXCLUDE`, are read.
- `running_total` of the corpus sums a scan's column of no origin, whose type the plan does not show, so no exact signature can be read and it stays noise.

## Review Focus

- A frame that excludes the current row: `1 FOLLOWING AND 2 FOLLOWING`, `2 PRECEDING AND 1 PRECEDING`, or any `EXCLUDE`.
- A `FILTER` on a window aggregate, and a window aggregate over a nullable column or the side a join extends.
- A grouping column, a `sum`, or an expression over `count` in a grouping-sets plan: all stay unproved.
- A `VALUES` cell that is `NULL`, a parameter, a cast, an expression or a prefixed string, and a `VALUES` joined by `UNION`.
- A `GROUPING` that is a user's function, which the plan prints quoted.
