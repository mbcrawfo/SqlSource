# TD-0079 items 3, 4 and 16: the describers' own errors, shared texts and folders

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mark PostgreSQL's own connection errors by an exception, as SQL Server does, write the four engine-neutral connection texts once, and settle whether the two describers' folders mirror each other.

**Architecture:** A new `PostgresConnection.UnusableException`, derived from `NpgsqlException`, carries every text the PostgreSQL describer throws of its own; `PostgresLive.AnswerAsync` catches it before any other `NpgsqlException` and answers its text as it is, so `OwnTexts` and `IsOwn` go.  A new `Describing/Describers/ConnectionTexts` holds `SessionRefused`, `ConnectTimedOut`, `NoAnswerInTime`, `LostConnection` and `Unreachable(prefix, SocketException)`, which both engines' `ConnectionErrors` use.  Item 16 follows the owner's answer.

**Tech Stack:** C# (.NET), Npgsql 10, Microsoft.Data.SqlClient, xUnit, Shouldly.

**Spec:** `docs/tech-debt/TD-0079-duplicated-logic-and-uneven-conventions-in-src.md`, items 3, 4 and 16.

## Global Constraints

- No change to what is generated, and no text a user sees changes but the PostgreSQL "unreachable" text, which loses a meaningless `: Success`.
- No capture or fixture changes: every text stays the same string.
- Touch only items 3, 4 and 16; TD-0079's other items keep their text and numbers.
- `PostgresConnection.UnreadableTypes` (td-0077) is one of the own texts and moves with the others.

## Where the code differs from the spec

- The spec says "an `UnusableException` caught in `PostgresLive.AnswerAsync`".  It derives from `NpgsqlException`, not `InvalidOperationException` as SQL Server's does (SQL Server's base is forced: `SqlException` has no public constructor).  Five catches of `PostgresLive` (`PrepareAsync`, `DeallocateAsync`, `InDescribeAsync`, `RestoreAfterFailureAsync` and `RefusedTransaction`'s filter) end or restore the describe's transaction on any `NpgsqlException`, and a lost connection, today an `NpgsqlException(LostConnection)`, must keep reaching them.  Deriving keeps each catch as it is.

## Review Focus

1. A lost connection inside a describe (`prepare`, a call in the transaction, `deallocate`) still ends or restores the transaction and answers `the connection to the server was lost`: the derivation keeps it; `SessionTests` of `tests/DatabaseTests/Postgres/Describer` pin it.
2. A driver's `NpgsqlException` whose message happens to equal an own text is now the driver's: test `AnswerAsync_DriverErrorWithAnOwnText_IsAnsweredAsTheDrivers` (Task 2).
3. An own text at `open` and at a later call passes unchanged: tests `AnswerAsync_UnusableException_PassesItsTextUnchanged` at open (`ConnectionErrors.AtOpen`) and later (`ConnectionErrors.Of`) (Task 2).
4. A text thrown by the describer as a plain `NpgsqlException`: test `PostgresDescriber_ThrowsNoNpgsqlExceptionOfItsOwn` scans `src/SqlSource.Tool/Describing/Postgres/` (Task 2).
5. A socket error of `Success` at `open` on PostgreSQL: `Unreachable` gives the prefix alone (Task 1).
