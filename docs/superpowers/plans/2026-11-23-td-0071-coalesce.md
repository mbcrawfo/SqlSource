# TD-0071 COALESCE of a non-deterministic argument Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SQL Server's `COALESCE` is proved not null only when no argument read twice can change between its test and its result.

**Architecture:** `COALESCE(a1, ..., an)` is proved when some `ak` is proved not null and every argument before it gives one value in a row.  A new walk, `OneValue`, proves that from the text and the `Stored` fact of `operands`.  `GREATEST` and `LEAST` keep their proof, since they read each argument once.

**Tech Stack:** C#, xUnit, Shouldly, SQL Server 2017 to 2025 in containers.

**Spec:** the unit's `td-0071-coalesce-spec.md`, and the tech-debt item of the `COALESCE` false non-null, which this change resolves and removes.

## Global Constraints

- A false non-null is the worst outcome and a false nullable only noise: an argument whose stability is in doubt leaves the column nullable.
- SQL Server's `Budgets` may rise in this unit.  Each column that moves is named in the PR description, with the change a user sees.
- Each shape that breaks has a test that runs it on a real server.
- `README.md` is not edited.  No new tech-debt id.

## Measurements

Five runs of 2,000 rows each, as `SELECT ... INTO`, on 2017 (CU31-GDR19), 2019 (CU32-GDR12), 2022 (CU27-GDR1) and 2025 (CU9-GDR1).  `flip` is `CASE WHEN ABS(CHECKSUM(NEWID())) % 2 = 0 THEN 1 END`.

| Shape | `NULL` rows of 10,000 |
|----|----|
| `COALESCE` of `flip`, `CAST`, `CONVERT`, `flip + 1`, `NULLIF`, `ISNULL(flip, NULL)`, `IIF`, a subquery of `flip`, a window over `NEWID()`, `SUM(flip) OVER` | about 2,500 |
| `COALESCE(flip, flip, 0)` | about 3,800 |
| `COALESCE(b, flip, 0)`, `b` a stored column | about 1,250 |
| `COALESCE(COALESCE(flip, NULL), 0)` | about 1,850 |
| `CHOOSE(random 1 or 2, 1, 2)`, which the server answers nullable | about 2,500 |
| `COALESCE` of a stored column, `b * 2`, `CAST(b)`, `NULLIF(b, 0)`, `MAX` or `SUM` without `OVER` | 0 |
| `GREATEST` and `LEAST` of `flip`, of its `CAST` and of a window over `NEWID()`, 2022 and 2025 | 0 |
| `IIF(random, 1, 2)`, `NULLIF(random, 3)`, `ISNULL(flip, 0)` | 0 |

The server names a source column only for a column, through a `CAST`, `CONVERT`, parentheses, a derived table, a CTE or an `APPLY`, never for an expression, a subquery or `NULLIF`.  An aggregate of `flip` without `OVER` gave no `NULL`, but no plan promises it, so its operand must give one value too.

## Review Focus

- A stable argument before an unstable one: `COALESCE(b, flip, 0)` stays nullable.
- An unstable argument after the proved one: `COALESCE(a, flip)` stays proved, since `flip` is never reached.
- A wrapper over an unstable value: `CAST`, `CONVERT`, `NULLIF`, `ISNULL`, a nested `COALESCE`, arithmetic, an aggregate.
- A grouping set's total, whose grouping column is `NULL` and stable: `COALESCE(g, 0)` under `ROLLUP` stays proved.
- A name that looks like a column but is none: `CURRENT_TIMESTAMP`, `@@ROWCOUNT`, a view's or a computed column.
