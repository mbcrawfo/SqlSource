## Where the code differs from the design, and what the plan settles

Recounted on 2026-10-23 against `main` at `677d626` plus pull request 2.

- **Two generated headers, not one.**  A file of queries starts with three lines (`// <auto-generated/>`, `#nullable enable`, `#pragma warning disable CS0108, CS0114 // ...`), in 11 snapshots (`GeneratedSourceTests` 5, `TypeEmitterTests` 5, `FileDiagnosticsTests` 1).  A model's file starts with the first two, in 16 (`ModelTests` 8, `ModelWarningTests` 4, `ColumnMarkerTests`, `SharedModelTests`, `SqlServerModelTests`, `TableModelTests` 1 each).  `GeneratedFile.Header` is the three lines and `GeneratedFile.ModelHeader` the two, so all 27 snapshots of the item name one constant.  `Header` is `ModelHeader` plus the pragma line.  A snapshot names its header as the first line of an interpolated raw string, `$$"""` then `{{GeneratedFile.Header}}`, so that it keeps its indentation and its lines stay within 120 columns (`$$$` where the snapshot holds a token's `{{`); the one whose header is followed by a line on the same line, a pragma of `ModelWarningTests`, is `GeneratedFile.ModelHeader + """...`.
- **The clean-run triple** is written out in 14 classes of `Generator/` (63 `GeneratedCodeWarnings.ShouldBeEmpty()`, of which 27 in `GeneratedSourceTests`), besides the four private `AssertClean`.  `ShouldBeClean()` replaces every place where all three are asserted together, the four `AssertClean` included.  A test that asserts only one or two of them keeps them.
- **The level helper.**  The level theories set a setting at a level named by a string, and the levels differ by class: `ModelTests` property, metadata, attribute and the file header; `TableModelTests` those and the query; `TypeOverrideLevelTests` property, metadata, the file header and the query.  `SettingLevel` names all five, and `LevelSettings` places one or more settings, each at its level, and gives the project's properties, the type's source and the `.sql` file.  A marker of the file header is followed by a blank line, as `ModelTests` and `TypeOverrideLevelTests` write it; `TableModelTests` wrote its header marker with none, which reads the same, since the file header is everything before the first `-- name:` line (`docs/manual/sql-files.md`).
- **The expected shapes in the rows.**  `ModelTests`' two kind theories take `(kind, expected)` rows, the expected text named once per kind in a field, in place of the `switch` and `Replace` inside the test.  `TypeOverrideLevelTests.Places` becomes `TheoryData<SettingLevel, string>`; `Run_KeyTwiceInOneMSBuildValue_TheLastWins` takes the place in its row; `Run_QuotedSchemaAndName_MapsTheType`, whose value and expectation differ between an MSBuild value and a marker, becomes two theories, `..._InAnMSBuildValue_MapsTheTypeAndSplitsAfterThem` (property, metadata) and `..._InAMarker_MapsTheType` (header, query).
- **Kind theories the item does not name.**  A sweep of every theory of `tests/SqlSource.Tests` for a `switch`, `if` or `==` on a row found four more whose row a `switch` turns into an arrangement of several parts: `SharedModelTests.Run_ModelsOfOneNameThatDiffer_AreSqlsrc257AtTheLaterMarker` (9 rows), `NpgsqlProbeTests.Read_EachDriver_GivesItsFlags` (4), `SqlClientProbeTests.Read_EachDriver_GivesItsFlags` (5) and `QueryTyperTests.Type_SqlServerTypeWithNoMapping_GivesTheHelp` (6).  They become facts, since the item is deleted here.  The rest of the sweep's hits pass a row on, or map it to one value (`SqlMarkerScopeTests`, `BuildFileTests`, the `Replace` theories of `SidecarReaderTests` and `SidecarSchemaTests`), and stay theories.  The container projects are outside the item.
- **`HintNameTests` is taken.**  `tests/SqlSource.Tests/Generation/Emitting/HintNameTests.cs` tests the type `HintName`.  The design's sixth class of `GeneratedSourceTests` is `GeneratedFileNameTests`.
- **`TextSpans` lives in `tests/SqlSource.Tests/Parsing/`**, beside `ParseOf`, since only the parser's tests use it, with `TextSpansTests` beside it.  `TestModels` gains `Literal` and `Query`.
- **The column markers**, which the parser gained after the design, go to `SqlFileParserMarkerTests` with the other markers of a query.

## Global Constraints

- Nothing under `src/` changes.  The allocation budgets of `SqlFileParserAllocationTests`, `PathResolverAllocationTests` and `SidecarReaderAllocationTests` are not touched.
- No test changes what it checks: a split moves a test unchanged; a fact made from a row keeps that row's arrangement and the assertions; a snapshot that names a header constant compares the same text.
- Everything that `tests/SqlSource.Tests/Generator/` or `tests/SqlSource.Testing` holds uses only API of Roslyn 4.8.0 and the packages RoslynFloor references.  Every new file of `Generator/` starts with the shared line its `AGENTS.md` gives, and its name ends in `Tests.cs`.
- Test names are `Method_Scenario_Outcome`; every test class is `public sealed class`; helpers are `internal`.
- Warnings are errors (`AnalysisLevel` `latest-all`); `ImplicitUsings` is off.  Comments in the plain declarative style of the files around them, two spaces after a full stop.
- Every commit passes `./pre-commit-validation.sh`.  Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **A snapshot whose text changes when its header becomes a constant.**  A raw string literal that follows `GeneratedFile.Header +` must begin with the blank line the snapshot had after the header.  The tests compare whole files, so a lost line fails; the review reads that every snapshot still ends as it did.
- **A row of a level theory placed at another level.**  `LevelSettings` must write each level exactly as the theory did (attribute arguments joined by `, `, query markers on the line after `-- name:` of the queries named).  `TypeOverrideLevelTests.Run_MappedTypeNotFound_...` puts its query marker under `GetFirst` and `GetSecond` and not `GetText`.
- **`Run_DefaultAtALevel_GivesTheBaseMapsType`** layers a key at every level below the default's; the rewrite keeps each row's layers.
- **A test lost in a split.**  The list of tests of `SqlSource.Tests` and `SqlSource.Tests.RoslynFloor` before and after differ only in moved classes and in the renamed facts and theories.
- **RoslynFloor.**  It builds and passes; `TestLayoutTests` passes on the new files.
