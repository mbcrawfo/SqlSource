# TD-0115 tool mutation gaps Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Settle the seven files of TD-0115's table by the item's procedure, and rewrite the item to what remains.

**Architecture:** Measure, then tests only where a behaviour has no guard.  The five files the tool's tests reach are run with their folder's tests and the command tests; the two live describers, which only the database projects reach, are judged by reading, and a gap a container can show gets a database test.

**Tech Stack:** C#, xUnit v3, Shouldly, Stryker.NET, PostgreSQL and SQL Server containers.

**Spec:** [`docs/tech-debt/TD-0115-tool-code-its-own-tests-do-not-check.md`](../../tech-debt/TD-0115-tool-code-its-own-tests-do-not-check.md).

## Global Constraints

- Scope: `WatchSession.cs`, `SqlServerLive.cs`, `DiagnoseRun.cs`, `PostgresLive.cs`, `DescribeRun.cs`, `RunEvents.cs` and `SidecarCheck.cs`.  The other files of the appendix stay in the item.
- No test only to raise a mutation score: each new test holds a behaviour a user or an answer depends on.
- A false non-null is the worst outcome of the describers.
