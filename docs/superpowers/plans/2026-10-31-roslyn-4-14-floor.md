# Roslyn 4.14 Floor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise the generator's Roslyn floor to 4.14.0, stop builds on older compilers with a clear error, and remove the 4.8.0 workarounds:

- the CS0436 suppressor (TD-0006);
- the copy of the row buffer in every methods file.

**Architecture:**

- The always-added attribute file gains `[Microsoft.CodeAnalysis.Embedded]` on its types, through `AddEmbeddedAttributeDefinition`.
- The two exceptions move to a source output of their own. It reuses a copy that a referenced assembly exposes, and otherwise writes one, internal or public.
- The row buffer becomes one embedded internal file for each compilation, written when any kept method uses it.
- A target in `build/SqlSource.targets` fails the build on a compiler older than 4.14.

**Tech Stack:** C# source generator (`netstandard2.0`, Roslyn 4.14.0), MSBuild package targets, xUnit v3 with Shouldly.

**Spec:** `docs/superpowers/specs/2026-10-31-roslyn-4-14-floor-design.md`

## Global Constraints

- **The Roslyn pin.** `Microsoft.CodeAnalysis.CSharp` is pinned to `4.14.0`.
  - The supported hosts are the .NET SDK 9.0.300 or later and Visual Studio 2022 17.14 or later.
  - Consumer projects still target .NET 8 or later and compile C# 12 or later.
- **The attribute file and the exceptions file compile as C# 7.3:** no `#nullable` and no `string?`.
- **Diagnostic ids are new and never reused.**
  - `SQLSRC021`: the compiler is too old (MSBuild).
  - `SQLSRC022`: the exceptions are seen in two or more assemblies.
  - `SQLSRC023`: the exceptions seen are of another shape.
  - `SQLSRC901` is deleted.
- **MSBuild property names start with `SqlSource`.** The new ones are `SqlSourcePublicExceptions`, `SqlSourceCompilerApiVersion` and the target `SqlSourceCheckCompilerVersion`. `CompilerApiVersion` is the SDK's own property, so it goes in `SdkProperties` in `BuildFileTests`.
- **New hint names:** `SqlSource-Exceptions.g.cs` and `SqlSource-RowBuffer.g.cs`.
- **The pipeline rules in `src/SqlSource/AGENTS.md` hold.**
  - No Roslyn object flows between steps.
  - Every `Collect()` is followed by a `Select` to a value-equal result.
  - Every new step has a `TrackingNames` entry.
- **The tests' API limit.** Every `.cs` file under `tests/SqlSource.Tests/Generator/` starts with the "Shared:" line and uses only Roslyn 4.14.0 API.
- **Repository rules** (root `AGENTS.md`):
  - Run `./pre-commit-validation.sh` before each commit, and `--full` before the push.
  - User docs describe effects only.
  - Each diagnostic has its section in `docs/manual/diagnostics.md` and a row in `AnalyzerReleases.Unshipped.md`.
  - The docs change in the same commit as the behaviour they describe.

## Review Focus

1. **`CompilerApiVersion` values compare as versions, not as strings.**
   - `roslyn4.9` must fail the check, though "4.9" sorts after "4.14" as text.
   - `roslyn4.14`, `roslyn5.0` and `roslyn10.0` pass.
   - An empty value, or one that does not match `roslyn<major>.<minor>`, does nothing. (Task 2)
2. **The shared-project workaround works end to end.** `DataShared` uses SqlSource and grants `InternalsVisibleTo` to `DataA` and `App`. `DataA` reuses `DataShared`'s exceptions, and `App`, which sees both, sees only `DataShared`'s copy and gets no `SQLSRC022`. (Task 3)
3. **Only copies the project can see count.** A reference whose exceptions are internal, with no `InternalsVisibleTo` for this project, is neither reused nor counted as a second copy. (Task 3)
4. **Reuse wins over `SqlSourcePublicExceptions`.** A project that reuses a referenced copy writes nothing, whatever the property says. (Task 3)
5. **A project with no queries and no attribute still gets the exceptions file**, since it is the `DataShared` of the workaround. (Task 3)
