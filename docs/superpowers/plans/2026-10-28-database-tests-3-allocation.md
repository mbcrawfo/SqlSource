# Database tests, piece 3: QueryMethodAllocation and the nightly jobs, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One project, `tests/DatabaseTests/QueryMethodAllocation`, holds every allocation test of a generated method on both engines, under one helper and one naming scheme, runs one test at a time, and runs only in two new jobs of `nightly.yml`, where a regression fails the job; `pre-commit-validation.sh`, `dotnet test --solution` and `build.yml` run none of them.

**Architecture:** The project links the query files and sidecars its tests call from each engine's `EndToEnd/Queries/` and claims them itself, so the generated methods it measures are the ones the engine projects run.  Each engine has a container subclass that builds `app` alone on the default image and a collection that holds it; the assembly turns parallelization off.  A property in the `.csproj`, `IsTestingPlatformApplication` false unless `RunQueryMethodAllocation=true`, keeps the new `dotnet test` from treating it as a test project, which the nightly jobs pass to `dotnet test --project`.  The two `AllocationTests` classes move in under one `Allocations` helper and one `Method_Scenario_Outcome` scheme, each keeping its measured constants, its connection state and its hand-written methods, and are deleted from the engine projects with their collections, the script's allocation trigger and `build.yml`'s two allocation arguments.

**Tech Stack:** .NET 10 SDK (10.0.401), the new `dotnet test` of Microsoft.Testing.Platform, xunit v3 4.0.1, Testcontainers 4.16.0, Npgsql 10 and Microsoft.Data.SqlClient 7, bash, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-28-database-tests-folder-design.md`, section "Piece 3: `QueryMethodAllocation`", with "Intent", "Goals", "Constraints" and "The layout".

## Review Focus

- A test that reads the project with a sidecar linked under another path would see a stale-sidecar error: pinned by Task 1's build, which fails on `SQLSRC` errors, and by `CheckTests` of the engine projects, which the full validation runs.
- A property that keeps the project out of `dotnet test --solution` but also out of `--project` would make the nightly jobs green with zero tests: pinned by Task 1's `dotnet test --project ... -p:RunQueryMethodAllocation=true`, which must run at least one test, and by Task 6's nightly run, whose summaries must list the tests.
- Two containers measured in one process at once would double what the commonest difference leaves out: pinned by the assembly-wide `CollectionBehavior` and each collection's `DisableParallelization`, which Task 2's and Task 3's runs exercise, and by the nightly jobs filtering to one namespace each.
- A sibling unit editing the same line of a shared document conflicts at merge: pinned by Task 5's limit to the listed lines.
- A plain `pre-commit-validation.sh` run that still filtered `*.EndToEnd.AllocationTests` would pass silently with nothing to filter; after Task 4 the script has no allocation branch, pinned by `grep -c allocation pre-commit-validation.sh` giving 0.
