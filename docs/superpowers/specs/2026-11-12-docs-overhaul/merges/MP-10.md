### The texts

#### `site/sql-files.md` 16

At the baseline: the paragraph on what a marker is, line 16.  Now: `site/reference/sql-files.md#marker`, word for word; its links are retargeted.

```text
A [marker](concepts.md#marker) is a line comment that starts its line and has the form `-- word: rest`, where the word is one SqlSource knows.  Nothing else in a comment is read.  The words are matched ignoring case, the blanks after `--` are optional, and the colon follows the word directly: `-- name: GetUser` and `--NAME:GetUser` are markers, `-- name : GetUser` is a comment.  A comment after SQL on the same line, or inside a block comment or a string, is not a marker either.  Under `mysql` and `mariadb` the two dashes need a space after them to start a comment at all, so there a marker needs one too: see [markers under `mysql` and `mariadb`](dialects.md#markers-under-mysql).
```

### The texts

#### `site/parameters-and-tokens.md` 29

At the baseline: the opening of `#query-parameters`, line 29.  Now: `site/reference/parameters.md#query-parameters`, word for word; its links are retargeted.

```text
SqlSource finds the parameters of a query: `@` and a name, outside strings, quoted identifiers, comments and hints.  A name is letters, digits and `_`.  Under `mssql` it is any character SQL Server takes in a variable's name: a combining mark, a letter number such as `Ⅰ`, a format character such as the zero-width non-joiner (but not the zero-width space, which SQL Server reads as a space and which ends the name), a connector such as `‿`, `$`, `#` and `@` among them, so `@xⅠ` and `@a$b` are one parameter each.  The list holds each parameter once, in the order it first appears.  The tool uses the list to ask a database what each parameter is, and the query's input [model](generator.md#models) has a property for each parameter in its order.  The [method](generator.md#query-methods) of a query whose output is `methods` or `repository` takes the input model as its argument `parameters`, and sends each parameter of the list by its name, with the value of its property: see [how a parameter is sent](generator.md#method-parameters).
```

#### `site/tool.md` 3-8

At the baseline: the first paragraph of `site/tool.md` and its sample, lines 3-8.  Placed by phase 5 at `site/reference/cli.md#tool`, under the h2 "The tool", which was the page's h1.  Its links are retargeted from `site/reference/`; its words are as below.

````text
The `SqlSource.Tool` package adds the `sqlsource` command to a project.  Its `describe` command connects to your database, asks it what the parameters and columns of each of your queries are, and writes the answers into [sidecar files](sidecars.md#sidecar-files) beside your `.sql` files.  You commit the sidecars with the project, so that a build needs no database.  On a machine that has a connection, the build [runs `describe` itself](msbuild.md#running-in-the-build) before it compiles.

```console
$ dotnet sqlsource describe --connection billing="Host=localhost;Database=billing;Username=app;Password=secret"
billing (postgres): 4 described, 0 skipped, 0 failed
```
````
