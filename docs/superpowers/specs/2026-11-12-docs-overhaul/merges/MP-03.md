## Namespace

Models are types of a namespace, not nested in the type that claims the query.  They are in the namespace of that type, or in the one that the [model namespace](#setting-model-namespace) names when it is set.  A type in the global namespace gives models in the global namespace. ### Namespace of the models

```sql
-- model-namespace: App.Models

-- name: ListUsers
SELECT id, name FROM users;
```

The namespace the generated [models](#models) go in.  The default is the namespace of the type that claims the file.  Above, the models of `ListUsers` are in `App.Models`.

- The value is C# identifiers joined by periods, none of them a reserved keyword or `file`, `required`, `scoped` or `extension`, which C# does not take as a type's name.
- It stands in the file header only.  It can also be `modelNamespace` in a settings file.

- Two types in two namespaces that claim one file, or read one table, get a model each, one in each namespace, unless this setting gives them one.
- A namespace that is, or starts with, the full name of a type of your project gives models whose names cannot be used: [SQLSRC258](../diagnostics.md#sqlsrc258).

The rules are under [Namespace](#model-namespace).
````

## Conflicts

None found.  The texts agree where both speak; the second has two facts the first lacks, the words `file`, `required`, `scoped`, `extension` and the case of one table, and the first has the global namespace.

- **The default and the global namespace.**  `TypeModels.Request` takes `settings.ModelNamespace` when it is set, and the type's `NamespaceValue` otherwise.  A type in the global namespace has an empty namespace, so its models are in the global namespace, as the first text says.
- **"Or read one table" is a second case.**  In `TypeModels.Request`, a table model is named after the table, and its namespace is the setting or the namespace of the type that asks for it, as for any model.  So two types in two namespaces whose queries read one table ask for two full names, one in each namespace, and get a table model each; a model namespace that both share gives them one full name.  `TableModelTests.Run_TwoNamespacesThatMatchOneTable_HaveAModelEachUnlessTheyShareANamespace` holds both: `App.UsersDto` and `Other.UsersDto`, or `Shared.UsersDto` alone with `"modelNamespace": "Shared"`.
- **The value.**  `SettingValue.IsQualifiedName` takes identifiers joined by periods, each of which `SqlIdentifier.IsUsableTypeName` takes: not a keyword, and not `file`, `required`, `scoped` or `extension`, as the second text says.
- **A full name.**  `TypeModels.Request` reads no namespace setting for a marker's name with a period, as the second text says.

## Namespace

```sql
-- model-namespace: App.Models

-- name: ListUsers
SELECT id, name FROM users;
```

The model namespace is the namespace that the generated [models](#models) go in.  In the sample, the models of `ListUsers` are in `App.Models`.  Models are types of a namespace, not nested in the type that claims the query.

- **The value is C# identifiers joined by periods.**  No identifier can be a reserved keyword, or `file`, `required`, `scoped` or `extension`, which C# does not take as the name of a type.
- **The default is the namespace of the type that claims the file.**  A type in the global namespace gives models in the global namespace.
- **The setting stands in the file header only.**  In a settings file, it can also be `modelNamespace`.
- **A full name ignores this setting.**  `-- input-model:` or `-- output-model:` gives a full name when the name has a period.
- **A namespace that is, or starts with, the full name of a type of your project gives models whose names cannot be used.**  That is [SQLSRC258](../diagnostics.md#sqlsrc258).
- **Two types in two namespaces get a model each, one in each namespace, in one of these cases:**
  - the two types claim one file, and each gets the models of its queries;
  - the two types read one table, and each gets a [table model](#table-models).

  This holds unless the model namespace gives the two types one namespace.
````
