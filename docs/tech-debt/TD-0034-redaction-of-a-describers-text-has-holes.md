# TD-0034 - What the removal of a connection's value from a describer's text does not cover

## Problem

Before a text that a describer gave is printed, [`Redaction`](../../src/SqlSource.Tool/Describing/Redaction.cs) writes the database's whole connection value as `***` wherever it stands, and each secret part of it where it stands as a token.  The parts are those the describer's `SecretsOf` gives, the PostgreSQL describer's `Password` and `SSL Password`, and [`ConnectionSecret`](../../src/SqlSource.Tool/Describing/ConnectionSecret.cs) holds the value with the parts it keeps.  [`DatabaseRuns`](../../src/SqlSource.Tool/Describing/DatabaseRuns.cs) applies it, to a failure's message once it is formatted too.  The log of `--log`, through [`SessionRunLog`](../../src/SqlSource.Tool/Logging/SessionRunLog.cs), and the lines of `--verbose`, through [`RunTrace`](../../src/SqlSource.Tool/Logging/RunTrace.cs), have the same removal, and [`EntrySecretCheck`](../../src/SqlSource.Tool/Describing/EntrySecretCheck.cs) ends the run when a describer put the whole value into an entry of a sidecar.  The PostgreSQL describer answers a session that could not be opened, or that the server ended, with the SQLSTATE and a fixed text of its own ([`ConnectionErrors`](../../src/SqlSource.Tool/Describing/Postgres/ConnectionErrors.cs)), so no driver's message of a connection is passed on.  These are outside all of it:

- **A capture.**  [`CapturingExchange`](../../src/SqlSource.Tool/Describing/Capture/CapturingExchange.cs) writes each answer as the describer gave it, and nothing searches a capture for the value or its parts.  A request holds nothing of a connection by the describer's rule, the request that opens a session is empty, and an `error` of `open` holds a fixed text, but an answer holds what the server said: a version, a setting, the message of a server's error of a query.  Nothing in the released tool records, so no capture leaves a machine today; from phase 10 a capture is the file a user attaches to a report.
- **A whole value that was changed, other than its parts.**  The whole value is found only as it is.  A driver's message that quotes it changed, trimmed of a trailing space or a line break for one, is printed, said and logged with each kept part written as `***` and the rest as it is: the host, the port and the user, which are no secret and are still the user's.  An entry that holds such a value is written.
- **A value spread over two members of one event of the log.**  `SessionRunLog` searches each string of an event alone, so a value that a describer writes half in one member and half in another is logged.
- **A part shorter than four characters.**  `ConnectionSecret` drops a part shorter than `ConnectionSecret.MinimumPartLength`, since a token of one to three characters matches too much ordinary text.  Such a password is printed and logged wherever a driver's message quotes it.
- **A part equal to a word the run writes of the database.**  `ConnectionSecret` drops a part that equals the database's logical name or the engine's canonical name, `postgres`, compared ordinally.  The run prints those words whatever the describer does, so hiding them hides nothing, and the password `postgres` would otherwise turn every error's `query:` line into `query: GetUser, database app, *** 16.4`.  A message that quotes such a password, `Password=postgres;`, keeps it.
- **A password that the driver reads from elsewhere.**  Npgsql takes a password from `PGPASSWORD` or a password file when the connection string gives none.  It is not in the value, `SecretsOf` does not give it, and nothing removes it from a driver's message.
- **An entry is searched for the whole value alone.**  `EntrySecretCheck` does not search for the parts.  An entry holds the names of a catalog and no driver's message, so a part found there would mostly be a name that equals a password, the password `password` beside a column `password` found through `SELECT *`, and `SQLSRC200` would end the run for a common schema.  The owner chose that over the search, so a describer that put a password into an entry would have it written to the sidecar.
- **A value that the sidecar holds without the describer.**  `EntrySecretCheck` finds a value only when the entry's text holds it and the same text without the describer's part does not.  A value that equals a word of the format, the engine, or the name of the query, of its database or of a parameter is so never found in what a describer gave.  No real connection string has that shape, and the file holds such a value whatever the describer does.
- **A value that equals a word of the describer's part of an entry.**  The text without the describer's part has no column and no type, so a value that equals a key that only those have, `origin` or `nullableSource` for two, ends the run with `SQLSRC200` when a query has a column.  That fails closed, and it is what is left of a wider case: a dummy value of a test or a replay such as `postgres` does not end the run.
- **A password that equals a whole word of what is printed.**  A kept part is removed wherever it stands as a token, so a password that equals a name the server quotes, a column `password` in `column "password" does not exist` with the password `password`, prints that name as `***`.  It leaks nothing and hides a word of the message.

## Why it exists

The tool does not read a connection string itself, so it knows of a value what the describer says: the passwords its driver reads from the value, and nothing of what the driver reads from elsewhere.  The token rule, the shortest part and the words of the run trade a little cover for output a user can still read: a dev password such as `test` leaves `latest_orders` alone.  The search of an entry for the whole value alone is the owner's decision, for the reason above.  A capture is left for the phase that first writes one for a user.

## Impact

Low.  A driver's message of a connection no longer reaches the output.  The container tests of `tests/SqlSource.Tests.Postgres` hold it: `SessionTests` checks that the failure of a wrong password, a missing database, an unreachable host and a terminated backend names neither the host nor the user, and `DescribeCommandTests` that a refused connection and a wrong password leave them out of everything printed and logged.  What is left needs a driver that quotes a changed value, a short password, a password that equals a word the run writes, or one from the environment, and the manual's known issue in [the tool's page](../manual/tool.md#known-issues) says to search a log for the password before sharing it.  A describer's rule is to put the value, or a part of it, in nothing it returns but `SecretsOf`, and this is the net under that rule, with these holes.

## Proposed fix

For a capture, before phase 10 writes one for a user: refuse to write a capture whose text, as `CaptureJson` writes it, holds the value or a secret part of it, as `EntrySecretCheck` refuses an entry, and decide with the first real describer what a server's message in an `error` may keep.  For a changed value, have a describer give the value as its driver writes it again, `NpgsqlConnectionStringBuilder.ConnectionString` for PostgreSQL, as one more part to remove whole.  For the log, have `SessionRunLog` also search the strings of an event joined.  For a password from the environment, have `SecretsOf` take the variables the driver reads, through `ToolHost.GetEnvironmentVariable`, so that the host stays the one way in.  Search an entry for the parts only if a describer is found to put a password in what it returns.

## Trigger

A user's report of a part of a connection in what the tool printed or logged.  For a capture, phase 10's `sqlsource diagnose`, which writes one for a user.
