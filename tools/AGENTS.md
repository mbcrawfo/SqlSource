# AGENTS.md - tools

This file holds the rules for changing the check scripts, the consumer project in `package-install/`, the script that pulls the test images and the two recording scripts.  [`README.md`](README.md) says what each of them does.

- **A check added here is added to both callers in the same commit**: `pre-commit-validation.sh` at the root and the `build` or `lint` job of `.github/workflows/build.yml`.  A check that needs the .NET SDK goes in `build`; one that needs only Docker goes in `lint`.
- **A new version of a linter is a change to the tag and the digest of its image in the script, and nothing else**, except that editorconfig-checker's also changes `Version` in `.editorconfig-checker.json` to match.
- **`package-install/` is a consumer, not a project of the solution.**  Do not add it to `SqlSource.slnx` or build it where it is.  A change to what a consumer sees from the generator or its MSBuild files adds a line to `package-install/Program.cs` and to `package-install/expected-output.txt` together.
- **Its multi-line values are deliberate.**  Do not put the values of `SqlSourceGeneratorParameters` and `SqlSourceDialect` in `package-install/Consumer.csproj` and `package-install/Directory.Build.targets` on one line: they are the test ([what they prove](README.md#check-package-installsh)).
- **`package-install/Queries/AddedByATarget.sql` is meant to be missing from the manifest.**  Do not delete the file or loosen the manifest check to make a run pass; the check fails when the manifest lists it, so paying off the debt it shows changes the script in the same commit ([the gap](README.md#check-package-installsh)).
- **`pull-test-images.sh` is a step of `build.yml`, not a check**, so it is not in `pre-commit-validation.sh`.  It reads both default images from `tests/SqlSource.Testing/DefaultImages.cs` by the lines that declare `Postgres` and `SqlServer`: a change to the shape of either line changes its `sed`, and the script fails when one gives nothing.
- **Keep the last run of `check-tool-install.sh`.**  It is the one check that the tool rolls forward from .NET 8 ([the run](README.md#check-tool-installsh)).
- **`record-fixtures.sh` and `describe-end-to-end.sh` stay out of `pre-commit-validation.sh` and `build.yml`** ([the scripts](README.md#recording-scripts)).  Both read a default image from `tests/SqlSource.Testing/DefaultImages.cs`, each by the line that declares it: `describe-end-to-end.sh` reads the line of `Postgres`, and `record-fixtures.sh` the line of the engine it records, `Postgres` for `postgres` and `SqlServer` for `mssql`.  A change to a line's shape changes the `sed` of each script that reads it, and a script fails when its `sed` gives nothing.  `AppContainer` in `tests/SqlSource.Tests.Postgres.Npgsql8` names the constant and reads no text.  `record-fixtures.sh` has one row for each engine in `engine_row`, and runs its class `FixtureCasesTests`, `SqlSource.Tests.Postgres.Describer` or `SqlSource.Tests.SqlServer.Describer`, with `SQLSOURCE_RECORD_FIXTURES=1`: renaming a test, its project or its variable, or adding an engine, changes the row in the same commit, and a test run with the variable set rewrites the recorded files.
- **`describe-end-to-end.sh` applies the files that `PostgresContainer` applies, in the same order**: `schema.sql` then `seed.sql` of `tests/SqlSource.Tests.Postgres/Realistic/`, `EndToEnd/app/` and `EndToEnd/billing/`.  A database added, renamed or moved there changes `DATABASES` in the script in the same commit, since the script names them itself.
- **`describe-end-to-end.sh` also describes `examples/PostgresExamples`**, after applying its `schema.sql` to the database `examples`, under the logical database `postgres`, the default, since the project sets no `SqlSourceDatabase`.  Moving or renaming the example, adding an example project, or setting `SqlSourceDatabase` in it changes `EXAMPLES` and the connection in the script in the same commit.

> Maintenance: this file names specific files and folders.  If you rename, move, or remove them, update this file in the same commit.
