# AGENTS.md - tools

This file holds the rules for changing the check scripts, the consumer project in `package-install/`, the script that pulls the test images and the two recording scripts.  [`README.md`](README.md) says what each of them does.

- **A check added here is added to both callers in the same commit**: `pre-commit-validation.sh` at the root and a job of `.github/workflows/build.yml`.  A check that needs only Docker goes in `lint`; one that needs the .NET SDK goes in the job whose build it shares, or in a job of its own.
- **A check's own script sets off that check in `pre-commit-validation.sh`**, as `format.sh` runs format on everything and `tools/actionlint.sh` runs actionlint, since a change to the script can change the verdict on any file it checks.
- **A kind of file is added to `is_known_kind` in `pre-commit-validation.sh` only after the trigger of every check that reads it handles it**, since a kind that is listed no longer makes the run full, and an unlisted one does.
- **`test-scopes.txt` is read by `pre-commit-validation.sh` and by `TestScopes` of `tests/SqlSource.Testing`**, so a pattern holds no glob character but `*`, since the C# reader refuses the others ([the format](README.md#test-scopes)).
- **A container test project that is added or removed gets or loses its `project` line in `test-scopes.txt` and its `RunningProjectTests` in the same commit**, and `TestScopesFileTests` of `tests/SqlSource.Tests/Validation/` names the four that exist.
- **A new version of a linter is a change to the tag and the digest of its image in the script, and nothing else**, except that editorconfig-checker's also changes `Version` in `.editorconfig-checker.json` to match.
- **`package-install/` is a consumer, not a project of the solution.**  Do not add it to `SqlSource.slnx` or build it where it is.  A change to what a consumer sees from the generator or its MSBuild files adds a line to `package-install/Program.cs` and to `package-install/expected-output.txt` together.
- **`package-install/Queries/AddedByATarget.sql` is meant to be missing from the manifest.**  Do not delete the file or loosen the manifest check to make a run pass; the check fails when the manifest lists it, so paying off the debt it shows changes the script in the same commit ([the gap](README.md#check-package-installsh)).
- **`pull-test-images.sh` is a step of `build.yml`, not a check**, so it is not in `pre-commit-validation.sh`.  It reads both default images from `tests/SqlSource.Testing/DefaultImages.cs` by the lines that declare `Postgres` and `SqlServer`: a change to the shape of either line changes its `sed`, and the script fails when one gives nothing.
- **Keep the last run of `check-tool-install.sh`.**  It is the one check that the tool rolls forward from .NET 8 ([the run](README.md#check-tool-installsh)).
- **`record-fixtures.sh` and `describe-end-to-end.sh` stay out of `pre-commit-validation.sh` and `build.yml`** ([the scripts](README.md#recording-scripts)).  Both read a default image from `tests/SqlSource.Testing/DefaultImages.cs`, each by the line that declares it: `describe-end-to-end.sh` reads the lines of `Postgres` and `SqlServer`, and `record-fixtures.sh` the line of the engine it records, `Postgres` for `postgres` and `SqlServer` for `mssql`.  A change to a line's shape changes the `sed` of each script that reads it, and a script fails when its `sed` gives nothing.  `AppContainer` in `tests/SqlSource.Tests.Postgres.Npgsql8` and in `tests/SqlSource.Tests.SqlServer.SqlClient61` names the constant and reads no text.  `record-fixtures.sh` has one row for each engine in `engine_row`, and runs its class `FixtureCasesTests`, `SqlSource.Tests.Postgres.Describer` or `SqlSource.Tests.SqlServer.Describer`, with `SQLSOURCE_RECORD_FIXTURES=1`: renaming a test, its project or its variable (`FixtureCaseRuns.RecordVariable` of `tests/SqlSource.Tool.Testing/Fixtures/`), or adding an engine, changes the row in the same commit, and a test run with the variable set rewrites the recorded files.
- **`describe-end-to-end.sh` applies the files that `PostgresContainer` applies, in the same order**: `schema.sql` then `seed.sql` of `tests/SqlSource.Tests.Postgres/Realistic/`, `EndToEnd/app/` and `EndToEnd/billing/`.  A database added, renamed or moved there changes `POSTGRES_DATABASES` in the script in the same commit, since the script names them itself.
- **`describe-end-to-end.sh` applies the files that `SqlServerContainer` applies on SQL Server 2025, in the same order**: `schema.sql` then `seed.sql` of `tests/SqlSource.Tests.SqlServer/Realistic/`, then `schema.sql`, `seed.sql` and `new-types.sql` of `EndToEnd/app/`, then `schema.sql` and `seed.sql` of `EndToEnd/billing/`.  A database or a file added, renamed or moved there changes `SQLSERVER_DATABASES` or the list of files in the script in the same commit.  Keep `-I` in `SQLCMD`, the image's `sqlcmd`, and `-f 65001` on the run of each file, so that the files run as `SqlServerContainer` runs them, with `QUOTED_IDENTIFIER` on and read as UTF-8; a default image whose `sqlcmd` is at another path changes `SQLCMD`.  Keep `--platform linux/amd64` on `docker run`, since the image is built for x64 alone.
- **`describe-end-to-end.sh` also describes `examples/PostgresExamples` and `examples/SqlServerExamples`**, each in its engine's part, after applying its `schema.sql` to a database `examples`, under the logical database of its dialect, `postgres` or `mssql`, the default, since neither project sets a `database`.  Moving or renaming an example, adding an example project, or setting a `database` in one changes `POSTGRES_EXAMPLES` or `SQLSERVER_EXAMPLES` and its connection in the script in the same commit.

> Maintenance: this file names specific files and folders.  If you rename, move, or remove them, update this file in the same commit.
