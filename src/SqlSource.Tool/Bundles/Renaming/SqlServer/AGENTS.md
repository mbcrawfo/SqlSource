# AGENTS.md - src/SqlSource.Tool/Bundles/Renaming/SqlServer

How SQL Server's part answers each member of the contract: [renaming for SQL Server](../../../../../docs/architecture/bundles.md#renaming-for-sql-server).

- **Every replacement comes through the scope**, `IRenamingScope.Parameter` and the rest, and `SqlServerMessages` writes no name of its own making: the token check trusts only the mapping's replacements and the engine's words.
- **A string member added to a record of `Describing/SqlServer/SqlServerCalls.cs`, or to the entry's SQL Server type, gets its rule in `SqlServerFields.cs`**, and never `FieldRule.Drop` while the pipeline reads it ([the fields](../../../../../docs/architecture/bundles.md#sql-servers-fields)).  A member with no rule is refused in every bundle that holds it.
- **`SqlServerVocabulary`'s lists are the union of what the floor and the default images know.**  When `VocabularyTests` or `CorpusWordsTests` of `tests/DatabaseTests/SqlServer/Renaming/` fail, add each engine word they name to its list, and each word of the user's to `CorpusUserWords`; never trim a list to make a test pass ([the vocabulary](../../../../../docs/architecture/bundles.md#sql-servers-vocabulary)).
- **Never put a word of the user's in the vocabulary**: an engine word is kept verbatim, and the proof cannot tell, since a renamed engine word still replays.
- **`SqlServerVocabulary.Fold` is the one fold**, of `Fold`, the vocabulary and the engine's rows but their schema, which is the server's only as it spells its own, `sys` or `INFORMATION_SCHEMA` by ordinal; upper-invariant by character.  It ignores case whatever the collation, and `Spelled` keeps each spelling's case apart; never fold by the collation, since a fold by ordinal splits `@Id` and `@id`, which the pipeline takes for one ([the fold](../../../../../docs/architecture/bundles.md#sql-servers-fold)).
- **`CopiesIn` reads a copy from the `parameters` request's `reused` alone, never from its spelling, and gives the suffix `_<position>` whatever the raw copy's separator, cut or number**, since that is what `ParameterCopies` makes from the renamed query, and a spelling cannot tell a cut copy or one of `@x_` from another's ([the copies](../../../../../docs/architecture/bundles.md#the-copies-of-a-reused-parameter)).
- **A message keeps only the `@name`s that `SqlServerErrors.NamesIn` reads**, the describer reading a message through the same method, a copy as its parameter through `IRenamingScope.ParameterOf`, since no decision reads more of it ([the messages](../../../../../docs/architecture/bundles.md#sql-servers-messages)).
- **Only SQL Server's code goes here**: `tools/test-scopes.txt` scopes the folder to `sqlserver`, so `pre-commit-validation.sh` runs none of PostgreSQL's container tests for a change here; what both engines need goes above.
