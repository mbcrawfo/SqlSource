# AGENTS.md - src/SqlSource.Tool/Describing/SqlServer/Proofs

How the SQL Server describer works: [`docs/architecture/sqlserver-describer.md`](../../../../../docs/architecture/sqlserver-describer.md).

- **The reader gives up rather than guess, and a misread must prove nothing.**  `TsqlTokens`, `SelectStatement`, `SelectBody` and `SelectItem` read a text they cannot follow as null, and a name they cannot read as a null `Name`, never as a likely answer: a column proved from a misread text is a silent wrong `false`.  A new form gets a test of what it must refuse beside what it reads.
- **A proof that holds for an expression that can be `NULL` is the worst bug here; one that gives up costs nothing.**  `ExpressionProofs` proves only the forms of the design's decision 2 ([`docs/superpowers/specs/2026-10-23-sql-server-nullability-noise-design.md`](../../../../../docs/superpowers/specs/2026-10-23-sql-server-nullability-noise-design.md)); a form whose condition fails is `Proof.No`, never a leaf to ask, and anything else unknown is a leaf or `Proof.No`.  Every new case comes with one that must stay unproved.
- **A leaf is asked only where the server's answer over the rows of the `FROM` and the `WHERE` holds in the item**: in the rows' context, or in the select's context unless the grouping is `Sets`; never when it holds, anywhere, an aggregate's name before `(`, `OVER` or a call of a schema's name.  `Proof` has no negation, and an operand is numbered only when its item's proof still needs it.  An item that is one leaf alone, its outer parentheses aside, asks nothing: `columns` answered that very expression over the same rows.
- **Depth is `SelectBody.DepthChange`, walked by `SelectBody.AtLevel` and `SelectBody.ClosingParenthesis`.**  Do not write another rule of depth.
- **`OperandsQuery`'s text is slices of the user's SQL, cut at token offsets, and nothing else but `SELECT`, `,`, line breaks and the aliases `AS [n]`.**  Never rewrite, quote or add to a slice: the text reaches the server only as `@tsql`, and the line break before each `AS [n]` keeps a line comment inside an operand from swallowing it.  An answer whose visible rows are not the operands one for one proves no operand.
- **`ColumnProofs` proves nothing for the whole query when one item disagrees with its column, in count, `*` or name**, and gives a proof only to a column the server answers nullable.  `Apply` only narrows: a column whose proof does not hold comes back as it came.
- **Nothing here sends anything.**  The reader reads the tokens of the user's text and calls no server, no exchange and no log; what a proof asks the server goes through the session's calls, by the rule of `Describing/SqlServer/` in `src/SqlSource.Tool/AGENTS.md`.
- **Tokens come from the generator's lexer, `DescriberSql.Lex` with `SqlDialectRules.SqlServer`**, so a comment, a string and a quoted name are split as the plan splits them.  Do not read the raw text for them.
