# AGENTS.md - src/SqlSource.Tool/Describing/SqlServer

- **`tests/SqlSource.Tool.Tests/SqlServerScript.cs` answers a `SqlServerSession` with no server**, from a capture that the test builds in code, so its tests hold what is asked as well as what is made of the answers ([fixtures](../../../../docs/architecture/sqlserver-describer.md#fixtures)).  What only a server can show, the types it infers, its columns and their origins, the tables it matches, its errors, what it runs and what SqlClient logs, is tested in `tests/SqlSource.Tests.SqlServer/Describer/`.
- **In `Describing/SqlServer/`, the user's text and a declaration reach the server only as the values of `@tsql` and `@params`** of `sys.sp_describe_undeclared_parameters`, called as a `CommandType.StoredProcedure`, and of `sys.dm_exec_describe_first_result_set` in the tool's own text (`Describing/SqlServer/SqlServerLive.cs`), through `columns` and `operands`, whose text is the query's own tokens rearranged (`Describing/SqlServer/Proofs/OperandsQuery.cs`), and are never put into a text the tool sends.  Both analyse a text and run nothing, so that is what keeps a `.sql` file from making the describer run a statement ([why a query cannot run a statement](../../../../docs/architecture/sqlserver-describer.md#why-a-query-cannot-run-a-statement)).  The canary tests of `tests/SqlSource.Tests.SqlServer/Describer/ParameterTests.cs` prove it through `parameters`, `probe`, `declared` and a describe, and those of `SafetyTests.cs` beside it through `columns`, each finding `dbo.victim` there after a text that drops it, and through `operands`, finding a sequence not advanced by an operand that takes its next value; a new place that sends a user's text sends it the same way and gets a canary beside them.  `DeclaredTypeText` is the first refusal, with an error that says what is wrong, and not the guarantee: the server reads `@params` as a list of declarations and refuses one that is not.
- **`SqlServerSession.DescribeAsync`, with `ResultAsync`, `ProvedAsync` and `MatchAsync`, holds the order of a describe** ([one describe, step by step](../../../../docs/architecture/sqlserver-describer.md#one-describe-step-by-step)): every declared type read before anything is sent; `declared` once for each declared parameter, before `parameters`, so that a `2715` or `2724` belongs to one declaration; the lists compared before any `probe`; a `probe` only for a reused parameter whose copies' types differ; `columns` once the parameters are typed, with every parameter declared; then `operands`, only when a proof needs the server, with the declarations of `columns`; and `table` only when every column has an origin in one table, since a call that fails for a table the match never reads would fail the query.  A `parameters` that fails with `11501` asks `columns` with the declared parameters alone, and `SqlServerErrors.AfterRefusal` reports the two answers.  A parameter is declared only when its `-- param:` marker gives a type.  The type of an inferred one is declared to `columns` by `SqlServerTypes.Declared`, a user type's names in brackets, and never by `Spelled`, which is for messages: the server refuses `dbo.User`, whose name is a keyword.
- **The copies of a reused parameter are renamed only through the lexer's `Parameter` lexemes, and a copy is ignored only when the probe binds it declared `xml` and declared `int`, never by the lexer's reading of what surrounds it** (`ParameterCopies`, [the copies and the probe](../../../../docs/architecture/sqlserver-describer.md#the-copies-and-the-probe)).  Every type in a sidecar is one the server gave, so the lexer never decides a type.
- **The calls of `Describing/SqlServer/` and their records are a contract with the captures** ([the calls and their records](../../../../docs/architecture/sqlserver-describer.md#the-calls-and-their-records)).  The names are `SqlServerCallNames`, added and never renamed, and the records are in `Describing/SqlServer/SqlServerCalls.cs`, with the rule of a record of a call that `tests/SqlSource.Tool.Tests/Describing/Capture/CallRecordTests.cs` holds.  A change to what the describer asks changes the fixtures: record them with `tools/record-fixtures.sh mssql` and read the diff.
- **SQL Server's connection is made in `Describing/SqlServer/SqlServerConnection.cs`, inside a `live` function and nowhere else, and every `live` function answers through `SqlServerLive.AnswerAsync`, where anything but a `SqlException`, an `UnusableException` or a cancellation is a bug** ([the connection](../../../../docs/architecture/sqlserver-describer.md#the-connection)).  SqlClient's texts name the host, the login or the value, so what reaches an answer is a fixed text of `ConnectionErrors`, and a replay touches no driver.
- **`SqlServerErrors` chooses an id by the error's number, or by the `error_type` of a row of `columns` or `table`, and never by its message** ([errors](../../../../docs/architecture/sqlserver-describer.md#errors)), since a message may be translated.  The message is read only to choose the parameter that `SQLSRC226` names.
- **`columns` and `table` read `sys.dm_exec_describe_first_result_set` in browse mode 2, and a hidden row is dropped before anything is built** (`SqlServerLive`, `SqlServerColumns`, [browse mode 2](../../../../docs/architecture/sqlserver-describer.md#browse-mode-2)).  Mode 1 names a view's base table as the origin and adds hidden columns that differ between versions, and mode 2's one hidden row, `ROWSTAT`, must reach no model.
- **A column's `nullable` is the server's `is_nullable`, narrowed only by a proof of `Describing/SqlServer/Proofs/` (`nullableSource` `expression`) or by a `PERSISTED NOT NULL` computed column read from its one table (`catalog`), and never widened; there is no plan walk, and every entry with rows records `plan` as `skipped`** (`SqlServerColumns`, `ColumnProofs`, [columns](../../../../docs/architecture/sqlserver-describer.md#columns), [the proofs of not null](../../../../docs/architecture/sqlserver-describer.md#proofs-of-not-null)).  What `operands` answers never fails the describe: an answer that proves nothing leaves the column as the server answered it.  The row's `PersistedNotNull` says what the catalog holds, not what the query reads: through an outer join the column is `NULL` and the server still names it as the source, so nothing but `ColumnProofs`, which reads the text for one table alone, acts on it.
- **A column has an origin only when its source is a table or a view of the session's database, the `DB_NAME()` that `open` reads** (`SqlServerColumns.OriginOf`, [origins](../../../../docs/architecture/sqlserver-describer.md#origins)).  The sidecar's origin names no database, so a column of another database, a linked server or the system resource must not match a table of the same name in the session's.  The source's type is the row's `SourceType`, the tool's own column of `columns`, and a table-valued function's column has none, since `SELECT *` from a function fails without its arguments.  `PersistedNotNull`, its other own column, is true only for a source of that same condition whose type is a table, `U`.
- **`table`'s text is built from the catalog names the server gave as the origin, and never from the user's text** (`SqlServerLive.TableSelect`): each name in brackets with `]` written twice.  `SqlServerTableMatcher` runs the format's checks through `TableMatchChecks`, the one order both matchers share (the server is asked for `table` only when its first two checks pass), and reads the table's columns and their nullability from `table`'s answer, the server's `SELECT *`, never from `sys.columns`, so that a hidden period column is out of the list, with its rows corrected by `ColumnProofs.TableRows` as the columns of a `SELECT *` from the table alone are, so that a corrected query is compared with a corrected table; a query that reads a `PERSISTED NOT NULL` column other than from the table alone (a join, a derived table, a CTE, an item in parentheses) keeps the server's answer and no longer matches, on `nullability-differs` ([the table match](../../../../docs/architecture/sqlserver-describer.md#the-table-match)).
- **SqlClient's events reach the log only through the allowlist of `Describing/SqlServer/SqlClientRunListener.cs`** ([driver logging](../../../../docs/architecture/sqlserver-describer.md#driver-logging)).  An event or a member is written only when it is listed, and none that can name the server, the database, the user or a password, nor a free-form `message`, is ever listed.  An `EventListener` is the process's, so the listener lives only as long as the session's connection: `SqlServerConnection` makes it for a log that writes and disposes it in `DisposeAsync`, on a failed open too, and a run without a log makes none.
