# AGENTS.md - src/SqlSource.Tool/Planning

- **`Planning/` makes the plan of a run and reports nothing.**  `Planning/RunPlanner.cs` gives a `RunPlan` and its errors as data, in the order they are to be reported, and `DescribeCommand.cs` reports them ([the plan](../../../docs/architecture/tool.md#the-plan)).
- **The plan keeps every query of every file that a type claims.**  `--database` and a `.sql` path set `PlannedQuery.IsSelected` and take nothing out, because a sidecar is written only when every query of its file that needs an entry has one.  A file that no type claims is never read.
- **The plan must agree with the generator**, on which type claims which file with which output, and on each query's hash.  So `RunPlanner` calls the generator's own path resolver, readers of settings files, parser and hash, through `Planning/SqlFileText.cs` and `Planning/RunSettingsFiles.cs`, and copies no rule.  `GeneratorParityTests` and the tests of `RunPlanner` hold the two together ([the plan](../../../docs/architecture/tool.md#the-plan)).  A rule that both need goes into the generator's project.
- **`Planning/AttributeReader.cs` reads syntax, and two arguments.**  It has no compilation, and reads `Path` as a string literal and `Output` as a member of `GeneratorOutput`, anything else in either being `SQLSRC208`, and nothing else on the attribute, since nothing else changes what is described ([the plan](../../../docs/architecture/tool.md#the-plan)).  What it misreads is `docs/tech-debt/TD-0031-attribute-reader-of-the-tool-is-syntax-only.md`.
- **A database belongs to a query that needs an entry, and to no other.**  Names are compared with `DatabaseName.Comparer`, ignoring case, and the plan holds the first spelling.
- **Only a `Ready` file decides its database's dialect or conflicts with it (`SQLSRC211`).**  A database that only other files hold keeps the dialect of the first of them.
- **Of the settings that are not valid, the tool reports the ones it reads**: `SQLSRC015` to `SQLSRC018`, and `SQLSRC019` of `dialect`, `output` and `database`.  The build reports the rest.
- **The problems of a settings file are reported once in a run, at their file, line and column, after the project's `SQLSRC208`**, for each settings file that a chain of the project's `.sql` or C# files reaches ([the plan](../../../docs/architecture/tool.md#the-plan)).
- **Neither the tool nor the build reads an MSBuild property or metadata for a setting.**
