# AGENTS.md - src/SqlSource/Generation/Repositories

- **No `ISymbol` or syntax node leaves `RepositoryShapeReader`, `GlobalMarkReader` or `GlobalConnections`; `ConnectionCandidateReader` and `HeldFactoryReader` are their helpers alone.**  The steps give `RepositoryShape`, `GlobalMark` and `DiagnosticInfo` records, compared by value, so that the steps after them stay cached.  See [records between the steps](../../../../docs/architecture/generator.md#records-between-the-steps).
- **`RepositoryShapes` reads, on every compilation, only the types of `RepositoryTypes`, those with a repository query, never inside `ForAttributeWithMetadataName`.**  That transform runs again only for a changed file, and a base type's member, a factory's or a type of the interface's name may be in another one; a type with no repository query costs it nothing.  `CachingRepositoryTests` holds both.
- **The global stage's `ForAttributeWithMetadataName` transform, `GlobalMarkReader.Read`, reads only the mark's own symbol; `GlobalConnections` decides everything else over the compilation**: whether the type is a repository, what the member gives and who can reach it, each of which may change in another file.
- **A broken global is reported once, by `GlobalConnections.Check`, and is never a candidate.**  A global in a generic or file-local type, or a type in one, is broken; `ConnectionCandidate.DisplayName` relies on the generic case, since it takes the text after the last dot or colon of `GlobalTypeText`.
- **`Check` passes over the statics of every `[SqlSourceGenerate]` type and of its base types**, which tier 1 reads and reports once for each derived repository; `CandidatesFor` offers a valid base static to every other repository, never to one that derives from its type.
- **The reader filters the candidates: only the marked ones when any is, the primary constructor's parameters only when no field or property is one, and of those only the ones that no base-type argument or initializer reads**, which `HeldParameters` names for `SQLSRC028`.  `HeldFactoryReader` filters `HeldCandidates` by the same parameter rule, and keeps only unmarked holders whose type has a marked member.  A step after it takes both as the readers' answer and filters nothing again.
- **`DbConnection`, `DbDataSource`, `Task`, `ValueTask` and `CancellationToken` are matched by name and namespace, never by a type's display, which carries a nullable annotation's `?`.**  The attribute is matched by its name, then `AttributeSource.ConnectionAttributeMetadataName`, never by a symbol the compilation looks up, so that a marked member of a base type in a referenced assembly matches too.
- **`ConnectionResolver`'s diagnostics go into `TypeMethods.Diagnostics`, never `TargetType.Diagnostics`,** which would cost the type its other files.  See [the plan](../../../../docs/architecture/generator.md#query-methods).
- **A type with no repository query is never resolved and takes no `RepositoryShape` into its `MethodsInput`**, so its marked members are never checked and a change to its candidates plans none of its methods again.  `RepositoryTypes.ClaimsRepositoryQuery` is the one rule of which types have one, for the gate and for `MethodsInput.Gather`.
- **Compare database names with `DatabaseName.Comparer`**, as the tool does: two names that differ only in case are one database.
